이 문서는 Y4 가 호스트하는 WaveTensor 가속기의 핵심 용어를 정리한다.
근거는 **WaveTensor 정본 `docs/wt64v1-architecture-guide/`**(이하 `G/`)이고,
Y4 의 capability 스키마·HIU ABI 문서·Verus/Coq 명세가 이 사전을 참조한다.

> **재출처 (2026-10-01).** 이 사전의 이전 판(§1–§10)은 WaveTensor 저장소 루트의
> legacy 참조 구현(`HIU.v` · `Pod.v` · `Cluster.v`)과 비정본 메모
> (`.claude-memos/wt64v1_spec.md`)에서 추출했다. WaveTensor 는 2026-08-20 부터
> 정본에 맞춰 RTL 을 clean-room 으로 전면 재구현하고 있다(SpinalHDL 주 +
> SystemVerilog 검증층, `rtl/`). 그래서 이 판에서 legacy 근거를 전부 걷어냈다.
> 옛 용어가 무엇으로 바뀌었는지는 §12 대응표에 있다.

> **재출처 (2026-10-16).** 정본 인용을 모두 WaveTensor `e88f6f4`(v1.0 동결 후보) 좌표 ·

ABI 근거가 될 수 없다.** 호스트가 보는 구성 표면(§2, 부록 E.1)은 재구현이 *새로

필요하다 (`e-defined.typ:9-16`, `03-hiu.typ:1608-1616`).

정본은 **pre-stable** 이다. 동결 보증은 `T_stable` 부터 발효하며, 그 값은 아직
비어 있다 (`00-preface.typ:36-54`, `G/appendix/b-gaps.typ:1797-1820`).

## 1. HIU (호스트 인터페이스)

**정의.** 호스트와 연산 패브릭 사이에 놓여 *호스트가 장치에 닿는 유일한 경계*.
호스트 요청을 받아 정당성을 판정하고 패브릭용 형태로 바꿔 넘긴다
(`G/chapters/03-hiu.typ:10-14`). 호스트는 연산 패브릭에 직접 닿지 않는다.
주소·구성·난수가 전부 HIU 를 지난다 (`03-hiu.typ:16-23`).

**네 역할** (`03-hiu.typ:41-50`):
1. **주소 변환** — PE 는 가상 주소로 메모리에 접근한다. 목적은 격리와,
   호스트 MMU 유무에 무관한 DVMA 다(§6).
2. **접근 승인** — 판정 경로는 상수 시간이다.
3. **구성 표면** — MMIO 레지스터(§2). ISA 의 논리 ID 사상표도 여기 산다.
4. **엔트로피 공급** — Pod 범위 난수(§7).

**요청 처리 순서** — 여섯 단계, 어느 경로든 같은 상태열 (`03-hiu.typ:62-74`):
접수 → 고정 지연 → 변환표 조회 → 물리 주소 마스킹 → 요청 실행 → 접근 승인.
조회 결과(적중/미적중)가 이후 단계의 개수를 바꾸면 안 된다. 승인(6)이 실행(5)
뒤에 오는 것은 의도다. 실행 단계는 승인 전에 외부에 관측 가능한 부수효과를 내지
않는다 (`03-hiu.typ:102-121`).

**상수 시간성** — 절대치가 아니라 *경로 간 동일성*이다. 적중·대체·미적중 세
경로가 완전히 같은 상태열을 지난다 (`05-security.typ:230-232`,
`appendix/c-glossary.typ:117`). 사이클 수는 계약이 아니라 귀결이다
(`05-security.typ:250-253`). 참조 구현에서 변환 시퀀스가 36→37 사이클로
늘어난 적이 있지만 계약은 유지됐다 (`05-security.typ:244-245`). ⇒ Y4 문서에
절대 사이클 수(예: 옛 Y4 판의 「≈32 cycle」)를 ABI 로 박지 않는다.

**호스트 주소 변환 서비스에 질의해 채우는 형태는 기각** (Y4 주: PCIe ATS/PRI 가
이 부류다. 정본은 「ATS」라는 낱말을 쓰지 않는다) — 질의 왕복은 가변 지연이라 상수 시간
계약과 양립하지 않는다 (`03-hiu.typ:178-191`). 재구현 요건: 변환은 장치 안에서
완결한다. 호스트 서비스는 선택적 가속일 뿐이며, 지원 호스트에서 기능이 늘어도
안 된다 (`03-hiu.typ:211-221`).

**HIU 는 문지기이지 운반자가 아니다.** 대량 데이터는 패브릭이 옮긴다
(`03-hiu.typ:232-238`).

> source: `G/chapters/03-hiu.typ` §3.1–3.3, `G/chapters/05-security.typ` §5.3
> (WaveTensor `f6bc4df`).

## 2. MMIO 구성 표면 (호스트가 보는 4 KiB 페이지)

구성 표면은 **4 KiB 한 페이지**의 32-bit 워드 맵이다. 영역 배치
(`G/appendix/e-defined.typ:44-57`, 부록 E.1):

| 범위 | 크기 | 내용 |
|---|---:|---|
| `0x000`–`0x11F` | 288 B | **물려받은 구역** — 뜻은 호스트 ABI 합의(§3.10) 대상. 합의 전 처분: 쓰기 거절 + `FAULT_STATUS[6]`, 읽기 0 |
| `0x120`–`0x1FF` | 224 B | 예약 (물려받은 구역이 늘어날 자리) |
| `0x200`–`0x2FF` | 256 B | 페이지 소유권 표 (§6) |
| `0x300`–`0x37F` | 128 B | 완료 방향 — 완료 링 · 완료 통지 · 드레인 관측면 |
| `0x380`–`0x3FF` | 128 B | 명령 방향 — 명령 링 |
| `0x400`–`0x7FF` | 1 KiB | LNID 소유 표 (256 × 4 B) |
| `0x800`–`0xBFF` | 1 KiB | LBID 사상표 (256 × 4 B) |
| `0xC00`–`0xDFF` | 512 B | 변환 항목 표면 — 파티션 기저 넷 · 기저마다 VPN · FRAME · COMMIT · VPN_HI + 예약-엄격 28 워드 · 기입 전용 · 형상 비노출 (§3) |
| `0xE00`–`0xE7F` | 128 B | 변환 저장소 제어 — flush · 미적중 관측 · 결속 파티션 `0xE14` (§3) |
| `0xE80`–`0xEFF` | 128 B | 마스킹 — 키 · 논스 · 재키잉 · 논스 중복 캡처 `0xEC4` (§5) |
| `0xF00`–`0xF3F` | 64 B | step 프로그램 적재 — FP_PROG · FP_BIND · FP_STATUS · `0xF0C` FP_SHAPE (아래 「step 프로그램 적재」) |
| `0xF40`–`0xF7F` | 64 B | 재조립 문맥 소거 |
| `0xF80`–`0xFBF` | 64 B | 장치 전역 fault (§8) |
| `0xFC0`–`0xFFF` | 64 B | 장치 식별 — `0xFFC` = ABI 판 (§10) · `0xFF8` HIU_SHAPE = 변환 형상 (§3, `docs/hiu_abi.md` §1.4) |

**페이지 전역 규칙:**
- **sub-word 쓰기 거절.** 기입 단위는 워드 하나다. 주소 하위 두 비트 ≠ 0 인 쓰기는
  페이지 어디서든 거절 + loud fault `FAULT_STATUS[6]` 이다. 비정렬 읽기는 0 이고
  fault 가 없다 (`03-hiu.typ:865-874`). 바이트 인에이블 절반(정렬 주소의 부분 바이트 쓰기)은
  장치 포트에 표현되지 않는다 — 그 이행 지점은 어댑터이고 정본 경계 밖 · 미측정이다
  (`03-hiu.typ:874`, `e-defined.typ:332`). Y4 는 구성 페이지를 자연 정렬 32b 전폭 load/store 로만
  접근한다(Y4 정책 — `docs/hiu_abi.md` §1.2.1 (C)). ⇒ 바이트 폭 레지스터의 워드 정렬 재배치는
  §3.10 합의 입력이었고, 3.10 v1.0 묶음(2026-10-09)이 「해당 없음」으로 닫았다(호스트 측
  소비자 0 — `03-hiu.typ:1640-1647`, `docs/hiu_abi.md` §5.3).
- **RO 워드** — 쓰기는 거절 + loud fault 다 (`e-defined.typ:202-204`).
- **워드 안의 예약 비트** — 엄격하다. 비0 기입은 거절 + loud fault 다
  (`e-defined.typ:188-190`).
- **표에 없는 오프셋** — 쓰기 무시 · 읽기 0 (3.7 예약 정책). 단 sub-word 쓰기와
  물려받은 구역은 위 두 규범이 따로 받는다 (`e-defined.typ:205-206`).
- **소비 회로가 없는 RW 워드** — 두 링의 base(`0x300`/`0x304` · `0x380`/`0x384`),
  `SQ_SIZE`(`0x388`), `SQ_TAIL`(`0x390`). 쓰기는 거절 + `[6]`, 읽기는 0 이다. 이는
  **소비 회로가 서기 전까지의 잠정 처분**이고, 회로가 서면 수락으로 넓힌다. 엄격 → 관대는
  하위 호환 방향이지만, 그 전제는 v1.0 적합 드라이버가 이 워드들에 쓰지 않는다는 것이고
  하위 호환의 판정은 방향어가 아니라 3.10 의 minor 기준이 한다 (`e-defined.typ:743`). 실물
  상태: 명령 링을 소비하는 회로는 0건이다 (`e-defined.typ:715-716`).
- **WO 워드** — 읽기 0, fault 없음 (되읽기를 주지 않는다, `e-defined.typ:198-201`).

**step 프로그램 적재 — `0xF00` 구역** (`e-defined.typ:453-466`). 공유 유닛의 step sequencer 에 프로그램을
싣고 선택 열쇠를 슬롯에 결속하는 표면이다. 슬롯 수 $P$ 는 구현 파라미터이고 $P$ ≥ 1 이다
(`02-fabric-alu.typ:488-490`).

| 오프셋 | 이름 | 접근 | 뜻 |
|---|---|:-:|---|
| `0xF00` | FP_PROG | WO | `[31:24]` 슬롯 · `[23:16]` step 색인 · `[15:0]` step 워드. MMIO 워드 필드에는 예약 비트가 없고, step 워드 *안*의 예약 `[15:14]` 는 배치가 진다. 거절 원인은 「`[15]` 의 원천」 (1) · (2) 이고 거절은 무효과다 (`e-defined.typ:459`) |
| `0xF04` | FP_BIND | WO | `[31]` en · `[30:24]` 예약 = 0 (엄격) · `[23:16]` 슬롯 · `[15:0]` 선택 열쇠. 「결속이 곧 상주 선언이다」. 「예약 검사가 먼저다」 — `[30:24]` 비0 은 `[6]` 만 서고 `[15]` 는 서지 않는다. en = 0 은 슬롯 필드를 무시하고 그 열쇠의 결속을 푼다(결속되지 않은 열쇠면 무연산). 이미 결속된 열쇠의 en = 1 은 *재결속*이다 — 옛 슬롯에서 이미 시작한 걷기를 멈추는가는 정하지 않는다 (`:461`) |
| `0xF08` | FP_STATUS | RO | `[0]` 적재 수락 가능(선택자 표 초기화 소거 완료) · `[1]` 걷기 진행 중 (`:463`) |
| `0xF0C` | FP_SHAPE | RO | **3.10 v1.0 묶음이 동결 전 호스트 측 대조로 신설.** `[8:0]` $P$ · `[17:9]` stepMax(슬롯당 step 수 상한) · `[23:18]` RO 예약 = 0 · `[31:24]` step 부호화 번호. 두 수는 *개수*로 인코딩하고 256 까지 담는다. 번호 1 = v1.0 배치, 0 = 「알리지 않음」. 「번호 ≠ 0 도 `0xFFC` ≠ 0 과 함께만 낸다」 — 판 값 전에는 워드 전체가 0 이고, 그동안 드라이버는 장치 밖(플랫폼)의 형상 지식으로 「`[15]` 의 원천」 (1) · (3) 을 피한다. 1 이 아닌 비0 번호의 장치에는 이미지를 싣지 않는다. 쓰기는 거절 + `[6]` (`:463`) |

- **배선은 아직이다.** 오늘 재구현은 `0xF0C` 를 미배정 오프셋처럼 다룬다 — 쓰기는 효과도 fault 도 없고 읽기는
  0 이다. 재구현 형상($P$ = 10 · stepMax = 32 — RTL 사실)에서 판 값 뒤의 읽기는 `0x0100_400A` 다
  (E.1.3 `e-defined.typ:738`, 3.9 `03-hiu.typ:1566`). 판 값 커밋은 이 배선과 함께이거나 그 뒤다(§10).
- **step 워드 배치 — v1.0 동결** (`03-hiu.typ:1692`). `[0]` last(1 = 이 step 뒤 걷기를 끝낸다) · `[1]` unit
  (0 = 공유 가산기 · 1 = 공유 곱셈기) · `[5:2]` srcA · `[9:6]` srcB · `[13:10]` dst · `[15:14]` 예약 = 0(엄격 — 비0
  적재는 거절 + `[15]`). 이 배치의 이름이 FP_SHAPE 부호화 번호 1 이다. **선택 열쇠** 16b 는 `[15:8]` 연산 종류 ‖
  `[7:0]` 정밀도이고, 동결하는 것은 두 필드의 자리와 폭뿐이다. 연산 종류의 번호 매김, 정밀도 필드에 넣을
  정밀도, step 의 실행 의미(래치의 쓰임 · 데이터 폭)는 동결하지 않는다. 「부호화 번호는 배치만 이름하고 실행
  의미를 식별하지 않는다」 — 이미지와 구현의 맞춤은 장치 밖(도구 사슬 · 플랫폼)의 일이고, 「v1.0 에는 실행
  의미를 식별하는 장치 워드가 없다」. ⇒ Y4 는 v1.0 에서 **플랫폼이 지정한 이미지만** 싣고, 테넌트는 선택
  열쇠로 고르기만 한다(2026-10-18 사용자 결정 U1 — `docs/hiu_abi.md` §1.1, `docs/y4_abi.md` §3).
- **runaway** — 「`[15]` 의 원천」 (4). 결속된 프로그램의 걷기가 종료 step(`[0]` last = 1)을 만나지 못한 채
  stepMax 개의 step 을 다 실행한 경우이고, 그 걷기는 결과 없이 끝난다. 원천 넷 가운데 실행 시점 원천은 이것
  하나다 (`e-defined.typ:464`). 「그 (4) 가 어느 결속 · 어느 걷기의 것인지는 v1.0 이 가르지 않는다」
  (`:466`). U1 아래에서 runaway 는 플랫폼 · 도구 사슬의 결함이다.
- **적재 의무 — E.1.1 「호스트 해석 규범」 4항** (`e-defined.typ:208`). 결속(en = 1)은 프로그램이 *마지막 장치
  reset 뒤에* 다 실리고 종료 step 을 가진 슬롯에만 한다 — 「step 프로그램 저장의 reset 뒤 내용은 정하지
  않는다」(`:216`). 「드라이버는 그렇게 맞춰진 이미지만 결속한다」. 결속된 슬롯에는 `0xF00` 를 쓰지 않는다.
  `[15:14]` 가 비0 인 step 워드는 싣지 않는다(남이 만든 이미지를 넘겨 싣는 경우 포함). `0xF00` · `0xF04` 기입은
  전부 `0x37C` DRAIN_ALLZERO = 1 아래에서 한다. **재적재**는 그 슬롯을 가리키던 결속을 모두 거둔 `0xF04`
  기입이 장치 포트에서 수락된 *뒤에* 수락된 `0xF08` 읽기가 `[1]` = 0 을 본 다음이다 — 해제 앞의 관측은 그
  사이에 시작한 걷기를 덮지 않는다. `[1]` 은 장치 전역 순간값이라 다른 열쇠의 투입이 이어지면 내려오지 않을
  수 있다. v1.0 장치는 이 순서를 판정하지 않고 수락하며, 어긴 순서는 조용할 수 있다(미적재 슬롯 결속 · 적재
  완료 전 결속 · 걷기 중 재적재 — `:466`).
- Y4 쪽 모형은 Verus `lease::step` 이다 — `step_word_ok` · `fp_prog_ok` · `fp_image_ok`(색인 0 부터 연속 n ≤ stepMax
  워드 · 마지막 워드 last = 1 — 정본보다 보수적인 Y4 정책) · 슬롯 장부(`SlotState` · `fp_mirror`) ·
  `fp_quiesce_action` · `StepGate` · `fp_shape_verdict`. 절차는 `docs/hiu_abi.md` §1.3 · §1.4 · §2.5 · §2.7.

## 3. 주소 변환 — 파티션 · 변환 항목 (옛 「partitioned TLB」 + 「shadow region」)

**파티션** — 격리 단위. 각 파티션은 자기 변환 항목 집합을 가지며, 파티션 간
변환 누출은 금지다 (`03-hiu.typ:512-515`). **파티션은 태그에 실리지 않는다.**
요청의 파티션은 「어느 임대 아래 도착했는가」가 정하며, 격리 판정의 입력은 구조이지
데이터가 아니다 (`03-hiu.typ:522-541`). 파티션 값을 기입으로 받는 표면은 넷이다 —
`0xE00` XLATE_FLUSH · `0xE14` XLATE_ACTIVE_PART · `0xEA0` MASK_PART · `0xEBC` MASK_REKEY.
넷 다 필드를 `[7:0]` 8 bit 로 고정한다 (`e-defined.typ:409-412`).

**결속 파티션 — `0xE14` XLATE_ACTIVE_PART** (RW). 「지금의 임대 = 파티션 p」를 장치에 알리는
표면이다. 태그에 실린 파티션이 아니라 드레인 경계에서만 바뀌는 구성 상태이고, 판정의 입력은
여전히 구조다 (`03-hiu.typ:1264-1294`, `e-defined.typ:329` · `:332`). WaveTensor 가 제안했고 Y4 의
조건 C1–C4 를 받아 정본에 실었다.
- 읽기는 `[7:0]` 현재 결속 · `[8]` APPLIED(A — 마지막 기입이 적용됐는가) · `[9]` DRAINED(D — 그
  기입 수락 에지의 드레인 판정)를 낸다. 쓰기는 `[7:0]` 값이고 `[9:8]` 은 쓰기 무시다(RW 워드 안의
  RO 필드). `[31:10]` 예약은 엄격이다.
- 값 검사가 먼저다 — 없는 파티션 값 · `[31:10]` 비0 은 A = 0 · 거절 + `[6]` · 결속 불변이다.
  현재와 다른 적법 값은 D = 1 일 때만 결속을 바꾸고, D = 0 이면 A = 0 · 거절 + `[6]` 이다. 같은
  값 기입은 D 와 무관하게 fault 없이 A = 1 과 D 를 보고한다. D 는 값 검사와 무관하게 그 기입
  수락 에지 직후의 상태(같은 사이클의 요청 접수 포함)를 표집하므로, A = 0 ∧ D = 1 은 값
  거절이고 A = 0 ∧ D = 0 은 값 거절이거나 드레인 위반이다. v1.0 의 D 는 `0x37C` DRAIN_ALLZERO
  다 (`e-defined.typ:332`, `03-hiu.typ:1306-1308`).
- 비정렬 `0xE15`–`0xE17` 쓰기는 이 정의역 밖이다 — 거절 + `[6]` 이고 A · D · 결속을 움직이지
  않는다. 정렬 주소 `0xE14` 의 부분 바이트 쓰기(바이트 인에이블 절반)는 장치 포트에서 표현되지
  않고, 그 이행 지점은 어댑터다 — 정본 경계 밖 · 미측정이다. 어댑터가 그 쓰기를 흘리면 장치는
  정의역 안의 전폭 `0xE14` 기입을 보므로, 「A · D · 결속 불변」은 그 절반에 대한 장치의 약속이
  아니다 (`e-defined.typ:332`).
- v1.0 결속은 격리를 주장하지 않는다. v1.0 에는 투입을 멈출 수단이 없어서, 격리 주장은 명령
  링 소비 회로가 착지한 판에서 한다 (`03-hiu.typ:1311-1320`, `e-defined.typ:332`).
- 재구현은 RTL 파도 W4(`e88f6f4`)에서 이 워드를 배선했다. HIU 요청 파티션의 구동은 결속
  레지스터 하나이고, 옛 최상위 요청 파티션 입력은 은퇴했다 (3.9 `03-hiu.typ:1556`).
- Y4 의 결속 전환 절차와 (A, D) 판정 처분은 `docs/hiu_abi.md` §1.3 · §2.4.

**변환은 장치 안에 있다.** 호스트는 변환 항목을 *기입*할 뿐이다
(`03-hiu.typ:165-171`). 그 표면이 **변환 항목 표면** `0xC00`–`0xDFF`(512 B, *형상 비노출*)이다
(`e-defined.typ:296-313`). 3.10 v1.0 묶음(2026-10-09)이 정했고, 재구현에는 RTL 파도
W3(`f67e3d6`)이 착지시켰다 (3.9 `03-hiu.typ:1552`).
- **파티션 기저** = `0xC00` + (p ≪ 7). `addr[8:7]` = 파티션이고 상한은 4 다
  (`e-defined.typ:298`). 512 B 의 근거는 파티션 2비트 × 파티션 기저 간격 128 B 다
  (`e-defined.typ:110`).
- 기저마다 아래 워드를 둔다. 전부 *기입 전용*이고 읽기는 0 이다 — 어느 항목이 상주하는지를
  돌려주는 표면은 없다 (`e-defined.typ:299`, `:305-308`).

  | 기저 + | 이름 | 필드 |
  |---|---|---|
  | `+0x00` | XLATE_ENTRY_VPN | `[31:0]` 가상 페이지 번호. 스테이징이며 열의 첫 워드 — 수락된 기입이 그 주소의 파티션을 래치한다 |
  | `+0x04` | XLATE_ENTRY_FRAME | `[31:0]` 물리 프레임(폭은 소유권 전이 워드와 같다). 스테이징 — 래치 파티션의 기저에서만 수락한다 |
  | `+0x08` | XLATE_ENTRY_COMMIT | `[31]` V(유효 — *유일한 방벽*) · `[30:28]` 권한 — `[30]` R · `[29]` W · `[28]` X · `[27:0]` 예약 = 0 (엄격). 기입이 스테이징과 함께 항목을 *단일 에지에 커밋*한다 |
  | `+0x0C` | XLATE_ENTRY_VPN_HI | `[31:0]` 예약 = 0 (엄격) — VA 확장 자리. VPN 워드의 일부로 취급한다 |
  | `+0x10`–`+0x7C` | 예약-엄격 워드 28 | 쓰기는 거절 + `[6]`, 읽기는 0 |

- 호스트는 (VPN, 프레임, 권한)만 기입하고 칸을 고르지 않는다. 파티션당 용량 · 연관도 · 교체
  정책 · 색인 함수 · 항목의 저장 폭은 *형상*이고 호스트 계약이 아니다 (`e-defined.typ:297`,
  `:764-765`). 페이지 크기는 **4 KiB 고정**이다. 가변 페이지는 상수 시간을 깬다
  (`e-defined.typ:777-778`).
- **규범은 형상이 아니라 인코딩이다.** 규범인 것은 파티션 필드 `addr[8:7]` 과 파티션 기저
  간격 128 B, 그리고 그것이 구조로 거는 상한 *파티션 ≤ 4* 다. 「파티션 4 × 항목 16」은 참조
  구현이 고른 형상이고 지위는 **측정**이다. 앞판의 *색인 ≤ 16* 상한과 태그 28b 등식은 호스트가
  색인을 고르던 표면과 함께 사라졌다. 파티션당 용량에는 인코딩 상한이 없고 `0xFF8` HIU_SHAPE 가
  정보로 알린다 (`e-defined.typ:791-803`, `03-hiu.typ:612-619`, B.5 「4 × 16」 행 *해소* —
  `b-gaps.typ:851-852`). ⇒ **동시에 보유된 임대(파티션 점유) ≤ 실재 파티션 수 ≤ 4** 다. 단
  드레인 후 교체(§4) 때문에 패브릭 안에서 진행하는 일은 어느 순간에도 한 테넌트의
  것이다 (`01-isa-asm.typ:1250-1253`).
- **임대 간 항목 분리**는 세 가지가 함께 준다. ⒜ 파티션 기저 주소 `addr[8:7]`.
  ⒝ 상한 아래 형상에서 없는 파티션 기저로 기입하면 어느 워드든 거절 + `[6]` 이고 스테이징을
  움직이지 않는다 (별칭 설치는 격리 위반, `e-defined.typ:423-425`). ⒞ 파티션 간 저장 용량
  비공유·교차 축출 금지 규범 (`03-hiu.typ:598-600`, SEC-4 · 결과 (c)). 주소 구조만으로는
  성립하지 않는다.
- **스테이징** — 장치에 하나다. 열은 VPN → FRAME → COMMIT 이고 VPN 유효 · FRAME 유효 둘을
  가진다. reset 은 빈 스테이징이다 (`e-defined.typ:311` (f)).
  - VPN 기입은 기입 주소의 파티션을 래치하고 FRAME 유효를 내린다. FRAME · VPN_HI 는 래치
    파티션과 같은 기저에서만 수락한다. 다르거나 VPN 유효가 없으면 거절 + `[6]` · 스테이징
    불변이다.
  - **FRAME 유효** — 수락된 FRAME 이 세우고, VPN 기입 · 수락된 VPN_HI 기입 · 래치 파티션의
    수락된 flush · reset 이 내린다. V=1 COMMIT 은 FRAME 유효를, V=0 COMMIT 은 VPN 유효만
    요구한다.
  - 다음 COMMIT 은 거절 + `[6]` 이고 아무것도 움직이지 않는다: 래치와 다른 파티션 기저 · VPN
    없음 · FRAME 유효 없는 V=1 · `[27:0]` 비0.
  - 커밋은 스테이징을 소진하지 않는다 — 같은 짝의 재커밋 · V=0 되풀이는 매번 커밋한다.
  - V=0 COMMIT 의 `[30:28]` 은 정의된 필드라 장치가 수락한다(V=0 항목은 적중하지 않아 관측되지
    않는다). Y4 는 V=0 COMMIT 을 `0x0000_0000` 으로 쓴다(Y4 정책 — `docs/hiu_abi.md` §1.2.1 (C)).
- **커밋 결과 규범 (a)–(h)** — 안쪽 방식은 자유이고 결과만 건다 (`e-defined.typ:310-312`).
  같은 (파티션, VPN) 에 두 항목이 동시에 적중하지 않는다 — 뒤 커밋이 앞 항목을 대체한다 (a).
  V=0 COMMIT 뒤 같은 (파티션, VPN) 조회는 반드시 미적중이다 (b). 축출은 같은 파티션 안에서만
  (c), 그리고 같은 파티션에 대한 COMMIT · flush 의 결과로만 일어난다 (h — 진행 보장). 미적중
  정지는 정지한 요청의 (파티션, VPN) 에 대한 V=1 커밋(거부 채움 포함)이 수락되면 풀린다 (d).
  Y4 쪽 정리는 `docs/hiu_abi.md` §1.3.
- **하류 정지** — 하류 채움 슬롯이 찬 동안의 적법한 COMMIT 은 버스를 배압으로 정지시킨다.
  정지는 장치 의무로서 유계 시간 안에 풀리고, 호스트 조치에 기대지 않는다. 주소 · 스테이징
  상태 사유의 거절은 기다리지 않고 곧장 거절 + `[6]` 이고, 데이터 필드 사유(FRAME 유효 없는
  V=1 · `[27:0]` 비0)는 *수락 사이클에* 거절된다 — 그 수락은 유계 정지 뒤일 수 있다
  (`e-defined.typ:308`). 재구현의 상한은 설치가 오지 않는 동안 ≤ `xlateParts` 사이클(무계
  증명)이고, 「실제 1 사이클」은 구조 논증이다 — 규범은 사이클 수를 걸지 않는다 (3.9
  `03-hiu.typ:1552`).
- 이 표면에서 생긴 용어:
  - **판정 시점** — 각 요청의 변환 판정(적중 · 프레임 · 권한)은 조회 지점에서 처음 적중한
    사이클에 정해지고, 요청이 조회 지점을 떠날 때까지 바뀌지 않는다. 래치된 판정은 승인 단의
    소유권 조회와 마스킹 입력에 같은 값으로 쓰인다 (판정 래치, `03-hiu.typ:729-737`). 재구현은
    RTL 파도 W2(`aa91e86`)에서 배선했다 (3.9 `03-hiu.typ:1555`).
  - **철회 효력 범위** — V=0 와 flush 는 그 에지 뒤에 *판정되는* 조회에만 효력이 있다
    (`03-hiu.typ:1322-1334`). 판정된
    요청은 옛 사상으로 끝까지 간다. 완전한 철회 = V=0 · flush + 에지 뒤의 드레인 관측. Y4 의
    프레임 회수 규칙은 `docs/hiu_abi.md` §2.7.
  - **예약-엄격 워드** — 표에 등재된 예약 워드(쓰기 거절 + `[6]`, 읽기 0). 「표에 없는 오프셋은
    쓰기 무시」(3.7)와 다르다. 첫 사례가 `0xC00` 파티션 기저 `+0x10`–`+0x7C` 이고, 근거는 앞판
    LO/HI 배치의 기입을 loud 로 만드는 것이다 (`e-defined.typ:215`, `:308`).
  - **파티션당 칸 수** — `0xFF8` HIU_SHAPE `[23:8]` 용량(`[7:0]` 은 실재 파티션 수). 정보 값이고
    정합성은 거기 기대지 않는다. 임의 VPN 집합의 동시 상주는 보장하지 않는다(직접 사상에서는
    하위 비트가 같은 VPN 끼리 서로 축출한다) (`e-defined.typ:503`). 재구현은 RTL 파도
    W1(`9b6eee6`)부터 참조 형상(파티션 4 × 칸 16, 직접 사상)에서 `0x0000_1004` 를 낸다 (3.9
    `03-hiu.typ:1556`). 판 0 장치도 이 값을 내지만, Y4 는 판 0 에서 이 값을 해석하지 않는다
    (`docs/hiu_abi.md` §1.4).
  - **상태 표면** — 5.8 관측면 부류. `0xEC4` MASK_DUP_CAPTURE(§5)와 `0xE14` 의 `[9:8]` A · D 가
    여기에 든다 (`e-defined.typ:329`, `:347`).

**옛 LO/HI 표면 (이력).** `645bed0` 정본까지 항목 표면은 직접 배열이었다 — 항목 주소
`0xC00 + (파티션 ≪ 7) + (색인 ≪ 3)`, `XLATE_ENTRY_LO`(+0x0 · 물리 프레임 · 항목 번호를 래치하는
스테이징)와 `XLATE_ENTRY_HI`(+0x4 · `[31]` V · `[30:28]` 권한 · `[27:0]` 태그 · 단일 에지 커밋).
WaveTensor 는 v1.0 에 파티션당 색인 16 고정(색인 = VPN 하위 4비트)을 제안했고, Y4 는 그 대신
색인 필드를 없애고 배치 · 용량 · 연관도를 장치 안쪽에 두는 표면을 제안했다. WaveTensor 가 받아
3.10 v1.0 묶음(`6a25359`)이 LO/HI 를 대체했고, 재구현의 LO/HI 문은 RTL 파도 W3(`f67e3d6`)에서
은퇴했다 (`e-defined.typ:297`, 3.9 `03-hiu.typ:1552`). 옛 표면의 항목 주소 `{파티션, 색인}` 을
인용하는 문서나 모델은 사라진 표면을 인용하는 것이다 (`03-hiu.typ:660-666`).

**적중** — 적중 키는 *(파티션, VPN)* 이다. 파티션과 VPN 이 모두 일치하고 V 가 설 때만
적중한다. 장치 안쪽이 VPN 을 색인과 태그로 갈라 저장하는 것은 방법이고, 키는 그 가름과
무관하다. 읽기 경로의 우선순위는 *진행 중 채움 바이패스 > 저장 블록 조회 > (선택적) 호스트
응답* 이고, 이 순서가 고르는 판정은 판정 시점에 래치된다. **대체(replace)** 는 형상 중립
정의다 — 조회한 (파티션, VPN) 이 상주하지 않는데, 그 VPN 이 앉을 칸이 다른 VPN 의 유효 항목으로
차 있는 경우다. 대체 경로의 조회도 아무것도 축출하지 않는다 (`03-hiu.typ:669-695`).

**미적중은 오류가 아니다** (`e-defined.typ:869-875`, 부록 E.3).
- 요청은 **배압으로 정지**하고, 미적중을 sticky 로 알린다. 정지는 조회 단 *전체*의
  정지다 (`05-security.typ:273-276`).
- 채움 주체는 **호스트**다. 장치는 채우지 않고 **타임아웃도 두지 않는다**
  (타임아웃은 조용한 실패다). 정지가 영구화되지 않게 할 책임은 호스트에 있다.
- 정지를 푸는 *항목 기입*은 정지한 요청의 (파티션, VPN) 에 대한 V=1 COMMIT(거부 채움 포함)의
  수락이다. VPN · FRAME 스테이징 기입과 V=0 COMMIT 은 정지를 풀지 않는다. 풀린 요청은 그 커밋
  항목으로 판정된다 (`e-defined.typ:873`).
- 관측: `0xE04` XLATE_STATUS(`[0]` 정지 중 · `[1]` sticky · `[15:8]` 정지한 요청의
  파티션), `0xE08`/`0xE0C` MISS_VPN. 값은 정지 게이트 스냅샷이고, 정지가 없으면
  0 이다. 읽기는 아무것도 해제하지 않는다 (`e-defined.typ:322-327`). MISS_VPN 값이 그대로
  정지한 파티션 기저의 VPN(· VPN_HI) 워드에 쓰인다 (`e-defined.typ:886-887`).
- sticky 해제: `0xE10` XLATE_MISS_CLEAR. **sticky 만 지우고 정지는 풀지 않는다.**
  정지를 푸는 것은 항목 기입뿐이다. 그래서 **드라이버 순서는 「항목 기입 → 해제」**
  다. 정지 중에 쓴 해제는 유실된다 (`e-defined.typ:328-329`, `:873`, `:888-890`).

**flush 는 데이터를 남긴다 — 영구 규율.** `0xE00` XLATE_FLUSH(`[7:0]` 파티션,
기입이 곧 발화)는 **그 파티션의 유효 비트만** 지운다. 태그·변환 데이터는 남는다.
V 가 *유일한 방벽*이다 (`03-hiu.typ:768-780`, `e-defined.typ:320-321`). 이 규율의
*컨텍스트 전환*은 임대 *회전*(§4)이다 — 살아 있는 임대 사이의 결속 전환(`0xE14`)은 flush 를
요구하지 않는다 (`03-hiu.typ:773-776`).
**전 파티션을 한꺼번에 비우는 전역 발화는 없고, 있어서도 안 된다**
(`e-defined.typ:1546-1547`). 수락된 flush 는 그 파티션을 래치한 스테이징의 *두 유효* — VPN
유효 · FRAME 유효 — 를 내린다(VPN · 프레임 값은 남는다, `e-defined.typ:321`). ⇒ flush 뒤 새
임대의 항목 기입은 **VPN 부터** 해야 하며, VPN 없는 FRAME · COMMIT 은 거절 + `[6]` 이다
(`e-defined.typ:1542`). 스테이징은 하나뿐이므로 VPN → FRAME → COMMIT 열은 호스트가
직렬화한다(정본 귀결).

> E.2 · E.3, `G/appendix/b-gaps.typ` 「4 × 16」 행.

## 4. 테넌트 임대 (tenant lease) · 임대 회전 · 드레인

**정의.** *파티션에 주소 변환 권한이 부여된 상태*. 영구가 아니라 회수
가능하다 (`03-hiu.typ:517-520`). **임대의 단위는 파티션이다**
(`05-security.typ:113`).

Y4 는 이 임대를 **hypervisor capability** 로 격상한다 (`docs/architecture.md`
§「Lease 의 OS-level 모델링」, `docs/lease_capability.md`). 장치에는 임대를 하나의
기입이나 이벤트로 다루는 표면이 없다. 임대 회전은 파티션 단위 표면(E.9 6항)을
차례로 쓰는 것으로만 표현된다 (`e-defined.typ:1538-1555`, `03-hiu.typ:517-525`).

**임대 회전 — 정본 E.9 6항** (`e-defined.typ:1538-1555`), *그 파티션에만* 건다:
1. ⑴ 호스트가 그 파티션에 대한 **투입을 멈춘다**(드레인 의무). ⑴ 은 p 가 `0xE14` 의 결속
   파티션인가로 갈린다. p 가 결속 파티션이면 ⑴ 은 결속 전환의 드레인과 같고, 관측은 장치 전역
   `0x37C` DRAIN_ALLZERO 로 한다. 그 드레인 안에서 미적중 정지는 관측면이 0 이 될 때까지
   *되풀이해* 해소한다. p 가 결속 파티션이 아니면 ⑴ 은 결속이 p 를 떠날 때의 판정(D = 1)으로
   이미 충족돼 있다 — 살아 있는 임대의 투입은 멈추지 않는다 (3.7.2 「드레인 의무의 범위」
   `03-hiu.typ:1215-1245`, 「결속 전환」 `:1284-1287`).
2. ⑵ `0xE00` XLATE_FLUSH 로 그 파티션의 변환 유효 비트를 지운다(데이터는 남음). 그 파티션을
   래치한 항목 스테이징의 유효도 이때 내려가므로, 새 임대의 항목은 VPN 부터 쓴다 — VPN 없는
   FRAME · COMMIT 은 거절 + `[6]` 이다(§3).
3. ⑶ `0xEA0` MASK_PART 를 그 파티션으로 두고, 새 키 8 워드 + 새 논스 6 워드를 기입한다.
4. ⑷ 발화 전에 `0xEC0` `[9]` = 1 을 확인한다 — 엔진이 바쁘면 `MASK_REKEY` 는 수락되지 않고
   fault 도 남기지 않는다. 그다음 `0xEBC` MASK_REKEY 로 발화하고, `0xEC0` `[8]`(엔진 busy)이
   내려갈 때까지 기다린 뒤 그 파티션의 준비 비트와 FAULT_STATUS `[6]` · `[12]` · `[13]` 을
   확인한다. 준비 비트만 기다리면 불완전하고 불충분하다. `[12]` = 1 이면 그 HIU 의 *모든*
   파티션의 준비 비트를 신뢰하지 않는다. 관측의 순서는 버스 수락 순서로 닫힌다 — `[8]` = 0 을
   본 MASK_STATUS 읽기 *뒤에 수락된* FAULT_STATUS 읽기는 최종 `[13]` 을 본다
   (`e-defined.typ:1543-1544`).

정본이 항목 기입에 대해 요구하는 것은 하나다. ⑵ 뒤 새 임대의 항목은 VPN 부터
쓴다(§3, `e-defined.typ:1542`). 순서를 어긴 구간의 요청은 **정지되지 않고
통과**하며, `FAULT_STATUS[11]` 「미준비 마스크 통과」가 사후에 크게 알릴 뿐이다
(`e-defined.typ:1551-1555`).

**Y4 측 선택:** 항목 기입(`0xC00`)은 ⑷ 뒤에 한다. 그리고 이 열 전체를
**단일 capability invocation 안에서 직렬화**해 게스트가 중간 상태를 보지 못하게
한다 (`docs/hiu_abi.md` §2.3–§2.4).

**결속 전환은 회전이 아니다.** 살아 있는 임대 사이의 전환은 투입 정지 → 드레인 → `0xE14`
기입 → 되읽기에서 `[7:0]` = 다음 값 ∧ A = 1 ∧ D = 1 확인 → 재개이고, flush · 재키잉이 없다
(`03-hiu.typ:1284-1290`).

**드레인 — 「기계에 드레인 모드는 없다」** (`03-hiu.typ:1180`). 구성(사상표·
flush·소유권) 교체는 *드레인 후 교체* 다. 비어야 하는 정의역은 여섯이다(요청
파이프라인 · 공유 유닛 보류 자원 · 생산자 출력/병합 · 진행 중 결과 슬롯 · 열린
재조립 문맥 · 미완료 순서 토큰, `03-hiu.typ:1166-1178`). 관측면은
DRAIN_ALLZERO(E.11, `0x37C`)다. 단 `DRAIN_ALLZERO = 1` 의 뜻은 「이 정의역이
비었다」이지 「장치에 비행 중인 일이 없다」가 아니다. 정본 규범은 이 구별을
적지 않는다(B.5 *조건부* — 정의역 밖 실행 주체를 두는 확장의 도입이 전건, `b-gaps.typ:1979-2004`). ⇒ 확장이 새 실행 주체를 들이면, Y4 는
재키잉·리셋·이주 전에 이 값 하나만 믿지 않는다. 3.7.2 「드레인 후 교체」의
귀결(해설)로, 패브릭은 공간이 아니라 **시간 분할**로 격리된다. 어느 순간에도
패브릭 안의 일은 한 테넌트의 것이다 (`01-isa-asm.typ:1250-1253`). 이를 완화하려면
3.7.2 와 패브릭 2.3 을 명시적으로 개정해야 한다 (`03-hiu.typ:527-529`).

> source: `G/chapters/03-hiu.typ` §3.6, §3.7.2, `G/appendix/e-defined.typ` E.9 6항,
> `G/chapters/05-security.typ` §5.2.2.

## 5. 주소 마스킹 · 마스크 키 · 논스

**정의.** 장치가 외부로 내는 물리 주소를 키스트림으로 가려, 관측자가 실제 접근
위치를 복원하지 못하게 한다 (`05-security.typ:86-88`). 마스크는 **표준 스트림
암호의 키스트림**이며 표준에 준거한다. 준거 대상은 확장 논스 스트림 암호
(XChaCha)이고, 기반 라운드 함수는 ChaCha (RFC 8439)다 (`05-security.typ:100-101`,
`:180-188`). 마스크는 물리 주소의 **페이지 프레임 부분에만** 적용하고 페이지 내
오프셋에는 적용하지 않는다 (`e-defined.typ:1522-1523`).

**표면 — `0xE80` 구역** (`e-defined.typ:338-347`):

| 오프셋 | 이름 | 접근 | 뜻 |
|---|---|:-:|---|
| `0xE80`–`0xE9C` | MASK_KEY[0..7] | WO | MASK_PART 파티션의 256-bit 키. 읽기 0. 기입은 그 파티션의 마스크 유효를 즉시 떨어뜨린다 |
| `0xEA0` | MASK_PART | RW | `[7:0]` 키·논스 기입 대상 파티션 (창). `[31:8]` 예약 = 0 (엄격) |
| `0xEA4`–`0xEB8` | MASK_NONCE[0..5] | WO | 그 파티션의 192-bit 논스. 읽기 0. 기입은 그 파티션의 마스크 유효를 즉시 떨어뜨린다 |
| `0xEBC` | MASK_REKEY | WO | `[7:0]` 재키잉할 파티션 p — 기입이 발화. `[31:8]` 예약 = 0 (엄격). 엔진이 유휴가 아니면 수락되지 않는다(무언 드롭 아님 — `[9]` 로 관측). 재키잉이 시작된 발화의 수락 사이클에 `[12]` 검사가 선다 — 마스크가 유효한 *다른* 파티션 q ≠ p 가운데 논스가 p 의 새 논스와 같은 것이 있으면 선다. *p 자신은 비교에 들지 않는다* |
| `0xEC0` | MASK_STATUS | RO | `[7:0]` 파티션별 마스크 준비 · `[8]` 엔진 busy · `[9]` 재키잉 수락 가능 |
| `0xEC4` | MASK_DUP_CAPTURE | RO | `[7:0]` `[12]` 를 세운 재키잉의 파티션 p · `[15:8]` 그 순간 마스크가 유효한 *다른* 파티션 q ≠ p 중 논스가 p 의 새 논스와 같았던 것의 비트맵(p 번 비트는 늘 0) · `[16]` 캡처 유효. 첫 사건 보존 · `[16]` ⇔ `[12]` · 해제는 `0xF84` `[12]`. 논스 값은 내지 않는다. 쓰기 거절 + `[6]` |

**규범:**
- **키는 임대마다 다르다.** 임대의 단위가 파티션이므로 장치는 파티션 수만큼 키를
  동시에 지고, 전 파티션이 키 한 벌을 공유하는 배치는 배제된다. 같은 파티션의
  연속 임대도 새 키를 쓴다 (`05-security.typ:112-116`, `e-defined.typ:1514-1521`).
- **키는 호스트가 구성 표면으로 기입한다. 장치는 키를 생성하지 않는다**
  (`e-defined.typ:1508-1513`). 장치가 키를 만들면 golden 대조(SEC-1)가 성립하지
  않는다.
- **키·논스는 WO** 다. 키 자료 추출 방어의 실물이다 (`05-security.typ:25-27`).
- **유일해야 하는 것은 `(키, 논스)` 쌍이다.** 「임대마다 새 키」의 유일성과 신선도는
  **장치가 강제할 수단이 없는 호스트(=Y4) ABI 의무**다. 키가 WO 이고 장치는 이력을
  지지 않기 때문이다 (`e-defined.typ:1514-1521`).
- **재키잉은 그 파티션의 flush 와 함께만** 일어난다. 한 임대의 키 기입이 다른
  임대의 마스크 유효를 떨어뜨리면 위반이다 (`e-defined.typ:1524-1528`).
- **`[12]` 「논스 재사용 재키잉」은 「논스는 파티션마다 다르다」의 건전한 부분 집행이다.**
  「발화하면 마스크가 유효한 *다른* 파티션 q 와 재키잉하는 p 가 같은 논스를 지고 있다는 뜻이므로
  위반이 실재한다」. 반대는 성립하지 않는다 — 마스크 유효가 떨어진 파티션은 비교에 들지 않는다.
  `(키, 논스)` 쌍 불변식에 대해서는 필요조건도 충분조건도 아니다 (`e-defined.typ:1558-1571`).
  재키잉은 `[12]` 와 무관하게 완료된다 (`b-gaps.typ:2085`). 겹친 상대는 `0xEC4` 가 낸다.
  ⇒ Y4 는 쌍 유일성을 자기 장부로 지고, `[12]` 는 보조 신호로 귀속한다(`docs/hiu_abi.md` §2.6,
  `docs/lease_capability.md` I3).
- 재키잉 때의 키·논스 바이트 **zeroize 규범은 정본에 없다**(reset 은 키 · 논스 = 0 —
  `e-defined.typ:216`). WaveTensor 비정본 메모는
  이를 개정 후보 G1 로 두고, 들인다면 단위는 파티션이라고 제안한다
  (`.claude-memos/y4_hiu_abi_signoff_response.md:514-526` — 메모의 제안이지 정본
  규범이 아니다). 2026-10-05 묶음에서 WaveTensor 는 G1 을 v1.x 개정 후보(B.5 재키잉
  자원과 함께 판단)로 받았고, Y4 는 발화 시점을 「`MASK_REKEY` 로 발화하되 소거는 엔진이
  키를 소비한 뒤 효력」으로 고쳤다(`docs/hiu_abi.md` §5.1 항목 1). 정본 B.5 는 「키·논스 바이트
  소거」를 v1.0 묶음이 모양까지 합의하고 v1.x 로 넘긴 다섯에 둔다 (`b-gaps.typ:2184-2186`).

**실물 상태 (rtl @e88f6f4):** 키·논스 저장은 파티션별이다(`MaskUnit.scala:286-287`,
`ca3c496` 에서 정본을 따라잡음). 키 기입은 자기 파티션의 마스크 유효만 내린다.
재키잉 연산 자원(라운드 상태·단계 기계·라운드망)은 한 벌을 공유하며, 규범은 이를
허용한다 (`05-security.typ:155-158`). 그 분리 여부와 면적 대가는 B.5 의 실물 되먹임 대기
항목이다 (`b-gaps.typ:2186-2191`). 재키잉은 43 사이클 고정이다(`MaskUnit.scala:165`).
`[11]` · `[12]` 발화와 `0xEC4` 캡처는 RTL 파도 W1(`9b6eee6`)이 배선했다 (3.9 `03-hiu.typ:1539` ·
`:1556`). `[12]` 의 논스 항은 고정 탐침 여섯의 *탐침 축약 아래* 측정이고, 세 비트 이상 ·
이웃하지 않은 두 비트 차이에만 나타나는 결함은 어디서도 전수로 재지 않는다
(`03-hiu.typ:1539`).

## 6. 페이지 소유권 · zero-copy · DVMA

**DVMA** — 장치가 물리 주소가 아니라 *가상 주소로* 메모리에 접근하는 것이다.
PE 는 호스트에 MMU 가 있든 없든 일관되게 DVMA 를 누린다 (`03-hiu.typ:147-157`).

**페이지 소유권 규약** (`03-hiu.typ:353-368`). 하드웨어 일관성이 없을 때 일관성을
대신하는 소프트웨어 규약이다 (`03-hiu.typ:313-319`):
1. 단위는 페이지이고, 상태는 **호스트 소유 / 장치 소유** 둘뿐이다.
2. 전이는 구성 표면의 명시적 쓰기로만 일어난다. 호스트→장치는 이양 기입이 *커밋될* 때 성립한다. 「이양
   기입은 형상 · 점유에 따라 거절될 수 있고」, 거절된 이양은 어느 페이지의 상태도 바꾸지 않는다 — 대상은
   호스트 소유로 남고 셋째 상태는 생기지 않는다. 회수 기입은 형상 · 점유로 거절되지 않는다
   (`03-hiu.typ:358-360`).
3. 넘기는 쪽이 비운다. 하드웨어 일관성이 있으면 이 의무만 생략할 수 있고, 소유권
   상태 기계 자체는 그대로 유지한다 (`03-hiu.typ:366-368`).
4. 소유하지 않은 쪽의 접근은 **loud fault (sticky)** 다. 관측 결과는 값 차단 +
   loud fault 다 (`03-hiu.typ:80-82`). 장치 쪽 접근의 보고 비트는 FAULT_STATUS `[19]` 「비소유
   프레임 접근」이고, 권한 비트가 그 접근을 허용하지 않으면 소유와 무관하게 `[4]` 가 대신 선다 —
   자격이 먼저다 (`03-hiu.typ:363`, §8). 3.9 의 이 축은 *부분*이다 — 후-formal 의 fault 축은 RTL
   파도 W1(`9b6eee6`)에서 섰고, HIU 파이프라인 단독 증명과 조립층 증명의 합성은 서술로 남는다
   (`03-hiu.typ:1551`).

표면 `0x200`: `OWN_IDX`(RW, 조회 대상) · `OWN_STATUS`(RO, `[0]` 장치 소유) ·
`OWN_SET`(WO, 장치로 이양) · `OWN_CLR`(WO, 호스트로 회수)
(`e-defined.typ:222-233`). 전이는 한 번의 쓰기로 완결되고, 완결은 커밋이거나 거절(무효과)이다 — 둘 사이의
상태는 관측되지 않는다 (`e-defined.typ:1379`). 전이 워드는 전 비트가 대상 프레임이다 (`:1382-1383`). 소유권
전이 워드의 프레임 폭과 변환 항목의 물리 프레임 폭은
**같아야 한다**. 두 폭이 같다는 *관계*가 계약이다. 그 공통 폭의 값은 32b 다 — 3.10 v1.0 묶음이
E.1.2 의 배정(`[31:0]`)을 그대로 고정했다 (`e-defined.typ:786-790`, `:1385-1386`).

**커밋과 거절 — E.7 6 · 7항, E.1.1 5항** (3.10 v1.0 묶음, 동결 전 호스트 측 대조 — 정본 `f6bc4df`):
- **OWN_SET 거절 (E.7 6항, `e-defined.typ:1387`)** — 형상 중립 정의다. 장치는 「그 프레임이 장치 소유로 앉을 수
  있는 저장 칸이 전부 다른 장치 소유 페이지로 차 있는 경우」 OWN_SET 을 거절할 수 있다. 거절은 무효과다 —
  어느 페이지의 상태도 바뀌지 않고, 대상은 호스트 소유로 남으며, 아무것도 축출하지 않는다. loud sticky
  `[7]` 을 세운다(§8). 어느 프레임이 거절되는가는 구현의 형상이 정하고 호스트 계약이 아니다. *하한* — 장치
  소유 페이지가 하나도 없을 때의 OWN_SET 에는 형상 · 점유에 따른 거절이 없다. 이미 장치 소유인 페이지의
  OWN_SET 은 무연산이다. OWN_CLR 은 형상 · 점유로 거절되지 않는다 (`:227` · `:229`).
- **읽기 순서 — 장치 포트에서 (E.7 7항, `:1388`)** — 프레임 f 의 전이 기입과 `0x200` OWN_IDX = f 기입이 장치
  포트에서 수락된 *뒤에* 수락된 `0x204` OWN_STATUS 읽기는, 그 사이에 f 의 다른 전이도 OWN_IDX 의 다른 기입도
  없으면 그 전이의 결과(커밋이든 거절이든)를 본다. 쓰기와 읽기가 그 순서로 장치 포트에 닿는가는 경계 밖이다
  — 「끝-끝 순서는 플랫폼의 성질이다」(Y4 전제 — `docs/hw_mechanism_abstraction.md` §2 구성 페이지 접근 속성 행).
- **되읽기 확인 의무 (E.1.1 「호스트 해석 규범」 5항, `:208`)** — 적합 드라이버는 OWN_SET 으로 넘긴 페이지를
  OWN_STATUS 되읽기가 `[0]` = 1 로 커밋을 확인하기 전에는 장치 소유로 셈하지 않는다. 이 의무가 있어서 소유권
  표의 형상 변경이 판의 일이 아니다(3.10 「언제나 major」의 예외 — 「이 예외는 E.7 6항의 정의 · 하한 ·
  OWN_CLR 의 형상 · 점유 무거절을 지키는 형상에 한한다」, `03-hiu.typ:1686` · `:1689`).
- **3.5 척추의 인정된 예외** — 재구현의 형상(직접 사상 64 칸 · 색인 = 프레임 하위 6비트 — RTL 사실)에서는
  장치 소유가 하나여도 다음 이양이 거절될 수 있다. 「이양할 수 있는가가 다시 호스트의 물리 주소 배치에
  기댄다」. 정본은 이것을 셋째 상태가 아니라 「동적이고 회복 가능한 용량 비용」으로 인정한다
  (`03-hiu.typ:415`, `:498`, B.5 「페이지 소유권 표의 용량 워드」 `b-gaps.typ:2121-2126`). ⇒ Y4 는 OWN_SET 마다
  되읽기로 확인하고, 거절되면 다른 프레임으로 상한 `K_OWN` 회(플랫폼 레지스트리 값)까지 다시 이양하며, 할당기에
  소유권 표 형상을 박지 않는다(2026-10-18 사용자 결정 U4 — `docs/hiu_abi.md` §2.7, `docs/y4_abi.md` §3).

## 7. 엔트로피원 (옛 「TRNG 채널」)

**네 단계** (`05-security.typ:329-334`):
1. 물리 엔트로피원 — 자유 발진 링 다수(참조 구현은 8개).
2. 편향 제거.
3. 건강성 검사 — 반복 계수 + 적응 비율, NIST SP 800-90B. 임계값은 사양에서 유도한다.
4. 조건화 — SP 800-90A 표준 조건화. 참조 구현에서는 범위 밖이었다.

참조 구현의 건강성 파라미터(창 1/임계 41, 창 64/임계 51)는 **측정**값이지
규범이 아니다 (`05-security.typ:337-340`).

**SEC-6** — 건강성 실패는 명시적 해제 전까지 유지된다(sticky). 실패 상태에서
생산된 난수는 소비자에게 *실패로 표시되어* 전달된다(poison)
(`05-security.typ:512-514`).

**호스트가 보는 면은 둘이다.**
- `FAULT_STATUS[17]` 「엔트로피원 건강성 검사 실패」(sticky, `e-defined.typ:522`).
  `0xF84` W1C 로 해제한다.
- 값 단위로는 완료 디스크립터 CD_TAG1 `[27]` poison 이 있다. 오늘 poison 의 유일한
  후보 원천이 `[17]` 이다 (`e-defined.typ:735-736`, `01-isa-asm.typ:1151-1153`).

둘 다 재구현에서는 상수 0 이다. **난수 값을 호스트가 읽는 워드는 E.1 신규 맵에
없다.** 물려받은 `0x000`–`0x11F` 의 뜻은 §3.10 합의 대상으로 남아 있다
(`e-defined.typ:44`). 난수의 소비자는 ISA 다. OPREF `src_kind = 2`
는 「난수 뱅크 (Pod 범위 64비트 조건화 난수)」다 (`01-isa-asm.typ:787-798`).

**실물 상태 (측정 트랙):** 엔트로피원 유닛은 재구현에 **미착지**다. 자리는 ABI
이지만 `[17]` 은 상수 0 이다 (`e-defined.typ:727-728`, `03-hiu.typ:1562`; rtl
`Wt64Top.scala:360`, `:1563`). 정본 §3.9 측정표의 「난수 공급」 행도 *미구현* 이다
(`03-hiu.typ:1538` — 2026-10-05 Y4 지적으로 정정).

**Y4 측 함의:** 장치는 키를 생성하지 않고 논스도 호스트가 기입한다
(`e-defined.typ:1508-1509`, `:1542-1543`). 그러므로 마스크 키·논스의 엔트로피 원천은
**호스트(Y4) 측**이다. `[17]` 관측 시의 정책(신규 임대 중단 등)은 **Y4 가 정하는
것이지 정본 요구가 아니다.**

정본은 마스크 키가 장치 엔트로피와 무관하다고 적는다: 「마스크 키는
엔트로피가 아니라 *호스트가 기입한다* … 주소 은닉의 강도는 키의 강도이지 장치
엔트로피가 아니다」(`03-hiu.typ:33`, 5.5 규범 블록 안의 예시 `05-security.typ:376` 도 같다).
두 곳이 장치 엔트로피가 마스킹을 먹인다고 서술하던 긴장은 2026-10-05 Y4 지적으로 해소됐다.

## 8. fault · 완료 통지 · 인터럽트

**loud fault** — 조용한 실패 금지가 원칙이다. 장치 전역 fault 구역은 다음과 같다
(`03-hiu.typ:1435-1437`, `e-defined.typ:494-499`, 비트 배정 `:509-527`):
- `0xF80` FAULT_STATUS (RO) — 원천별 sticky 비트맵(접지 않음). Y4 가 자주 마주칠
  비트: `[4]` 변환 권한 위반(자격 거부), `[6]` 거절된 구성 기입, `[11]` 미준비 마스크 통과,
  `[12]` 논스 재사용 재키잉, `[13]` 재키잉 중 입력 기입, `[17]` 엔트로피 건강성, `[19]` 비소유 프레임
  접근. v1.0 배정은 `[0]`–`[19]` · `[31:20]` RO 예약이고, 배정은 v1.0 에서 동결한다 — 새 원천은
  v1.x 에서 `[31:20]` 의 새 비트로만 연다 (`e-defined.typ:495` · `:509-527`).
  - `[6]` 은 원천이 여럿인 sticky 다. 재구현 안에서는 원천별 sticky 를 합친 것이다(`0xC00` 문 ·
    `0xE14` 거절 포함 — 3.9 `03-hiu.typ:1552` · `:1556`). 정본은 거절된 기입의 `[6]` 이 `0xF80` 에
    보이는 사이클을 걸지 않는다. 그래서 Y4 는 `0xE14` 판정을 (A, D) 되읽기로만 한다. A = 0 이면
    되읽기 응답 뒤 `[6]` = 1 을 유계 폴링으로 확인하고 `0xE14` 몫으로 귀속해 `0xF84` `[6]` 하나만
    해제한다 — 분기보다 먼저다. 폴링이 소진되면 거절의 loud 부재로 보고 `DeviceFault` 로
    처리한다. A = 1 이면 `[6]` 을 기대하지 않는다(Y4 정책 — `docs/hiu_abi.md` §2.4).
  - `[12]` — 재키잉하는 p 의 새 논스와 같은 논스를 마스크가 유효한 다른 파티션 q ≠ p 가 지고
    있을 때 선다(p 자신은 비교에 들지 않는다 — `e-defined.typ:345`). 강등 유지이고, 겹친 상대는
    `0xEC4` 가 낸다(§5). `[12]` = 1 이면 그 HIU 의 모든 파티션의 준비 비트를 신뢰하지 않는다
    (`e-defined.typ:1544`).
  - **창 거절 집합 W** = `[5]` · `[6]` · `[7]` · `[15]` — Y4 가 전역 구성 창의 기입 뒤 `T_FLT` 를
    기다려 확인하는 거절 loud 비트들이다(`docs/hiu_abi.md` §1.3 · §2.4 3 — `[5]` · `[6]` 만 정지
    `LeaseInvariant` 에 이른다. 설명된 `[7]` 은 `OwnSetRefused`(`K_OWN` 재시도 소진 때만 테넌트에 거친 「풀 확장 실패」), `[15]` 는 운영자 · 플랫폼 기록
    `StepUnattributed` 뿐이다 — Verus `lease::window`). `[6]` 밖의 셋:
    - `[5]` 「구성 — 소유 서로소 위반 (D2)」(`e-defined.typ:519`) — LNID V=1 기입의 서로소성(1.4.5)
      위반은 `[6]` 에 접지 않고 `[5]` 가 따로 받는다(`03-hiu.typ:1096`). 엔트리를 쓰는 주체는 Y4
      뿐이라 시점과 무관하게 Y4 결함이다.
    - `[7]` 「페이지 소유권 표 충돌 — 형상 · 점유에 따른 `0x208` OWN_SET 거절 (E.7 6항)」
      (`e-defined.typ:521`) — 원천은 E.7 6항의 OWN_SET 거절 *하나*다(`:527`, §6). 적합 순서에서도 일어나는
      거절이라 `[6]` 에 접지 않고, CAP_STATUS(능력 부재)로도 보고하지 않는다. 캡처(프레임)는 없다 — 어느
      이양이 거절됐는지는 E.1.1 5항의 되읽기가 가른다(`:529` 해설). 재구현은 64칸 직접 사상의 충돌 이양
      기입을 「쓰기 무효 + loud sticky fault」로 낸다(RTL 사실: `rtl/spinal/src/main/scala/wt64/hiu/OwnershipTable.scala:92-96` ·
      `:318-336` — 정본 3.9 행이 무축출과 `[7]` 의 완전성은 재지만 *상승 건전성*은 일반으로 재지 않는다,
      `03-hiu.typ:1537`). 그래서 Y4 는 OWN_SET 마다 `OWN_STATUS` 되읽기로 커밋을 확인하고 확인된 프레임만
      장부에 올린다. 되읽기가 거절을 보여 설명된 `[7]` 은 `OwnSetRefused`(`[7]` 해제 · 테넌트에는 `K_OWN` 재시도 소진 때만 거친 「풀 확장 실패」),
      설명되지 않는 `[7]` 과 `[7]` 없는 거절은 장치 모순(`DeviceFault`)이다.
    - `[15]` 「step 프로그램 불량」(`e-defined.typ:520`) — 원천은 *닫힌 넷*이다(`:464`, §2 「step 프로그램
      적재」). 「그 밖의 원천은 `[15]` 에 접지 않는다.」 (1) FP_PROG 의 용량 밖 슬롯 · step 색인, (2) step
      워드 예약 자리 `[15:14]` 의 비0, (3) FP_BIND en = 1 의 용량 밖 슬롯(`[30:24]` = 0 인 기입에 한함),
      (4) runaway. (1)–(3) 은 기입 시점의 무효과 거절이고 (4) 만 실행 시점 원천이다. 재구현의 발화선도 이
      넷과 같다(RTL 사실: `rtl/spinal/src/main/scala/wt64/fp/StepSequencer.scala:296` · `:309` · `:460-462`).
      Y4 는 (1) · (3) 을 `0xF0C`(판 0 동안은 플랫폼 레지스트리)로, (2) 를 `step_word_ok` 내용 검사로 기입 전에
      배제하므로, Y4 가 보는 `[15]` 는 (4) 이거나 Y4 · 플랫폼 쪽 의무 위반이다. 「그 (4) 가 어느 결속 · 어느
      걷기의 것인지는 v1.0 이 가르지 않는다」(`e-defined.typ:466`) — 그래서 Y4 는 `[15]` 를 임대에 귀속하지 않고
      (`StepUnattributed` — 기록 · 해제만), 정지하지도 않는다. FP 관문(적재 뒤 `T_FLT` 대기 · `[15]` 확인)은
      방어용으로만 남는다 — 1차 `[15]` 면 기록 · 해제 · 같은 이미지를 한 번 다시 싣고, 2차도 `[15]` 면 결속하지
      않고 `DeviceFault` 다(2026-10-18 사용자 결정 U2 — `docs/hiu_abi.md` §2.7).
    - `[7]` · `[15]` 의 원천 정렬(Y4 물음 D1 · D2)은 `f6bc4df` 가 정본 규범으로 닫았다 — 「`[7]` 과 `[15]` 의
      원천은 동결 전 호스트 측 대조가 문면으로 닫았다」(`e-defined.typ:527`). 동결 뒤 기존 비트에 새 원천을
      접는 것은 major 다(`03-hiu.typ:1683-1686`).
  - **비소유 프레임 접근** `[19]` — 자격(권한 비트)은 허용했으나 승인 단의 소유권 판정이 장치
    소유가 아니라서 거부된 접근. *자격이 먼저*라 권한 불허는 소유와 무관하게 `[4]` 만 세우고, 한
    접근에 둘이 함께 서지 않는다. 거부 채움(V=1 · R = W = X = 0)은 프레임이 무엇이든 `[4]` 로만
    선다. 3.10 v1.0 묶음이 동결 전 호스트 측 대조(Y4 요청 — 정정 `8af46df`)로 `[4]` 에서 갈라
    신설했다 (`e-defined.typ:527`). 재구현은 RTL 파도 W1(`9b6eee6`)부터 원인별로 낸다 (3.9
    `03-hiu.typ:1539`).
- `0xF84` FAULT_CLEAR (WO) — 같은 배치의 W1C · `[31:20]` 예약 엄격(비0 이면 기입 전체 거절 + `[6]`,
  한 비트도 내리지 않는다). 해제와 발화가 같은 사이클이면 발화가 이긴다. 호스트 대면 fault 해제
  표면은 이 워드 하나다 — `[19]` 의 해제도 `0xF84` `[19]` 하나다 (`e-defined.typ:497`,
  `03-hiu.typ:1539`).
- `0xF88` FAULT_SUMMARY (RO) — `[0]` 논리합. 개별 노출에 덧붙는 값이다.

**완료 통지** — **완료 링에 항목을 넣는 것이 유일한 통지 수단이다**
(`e-defined.typ:1329`). **인터럽트는 선택적 가속**이다. 마스크로 끌 수 있고, 끄면
호스트가 완료 링을 폴링하며 기능은 줄지 않는다 (`e-defined.typ:1330-1332`).
표면은 `0x320` IRQ_STATUS(sticky) · `0x324` IRQ_MASK(**reset 값 1 = 기본 폴링**) ·
`0x328` IRQ_CLEAR 다 (`e-defined.typ:258-263`). 인터럽트를 정상 경로의 전제로 두지
않는다 (`e-defined.typ:1365-1367`).

**실물 상태 (rtl @e88f6f4):** 최상위 인터럽트 선은 하나이고, set 원천은 완료 링
삽입 하나다 (`rtl/spinal/src/main/scala/wt64/host/CompletionUnit.scala:601-602`).
**정본:** E.6 은 완료 통지 외의 IRQ 원천을 정하지 않는다. FAULT_SUMMARY 의 IRQ
편입은 WaveTensor 요청 채널(비정본)이 「G2」로 올린 개정 후보(v1.x)다. 정본 B.5 는 「fault 의
인터럽트 경로」를 v1.0 묶음이 모양까지 합의하고 v1.x 로 넘긴 다섯에 둔다
(`b-gaps.typ:2184-2186`). Y4 는
2026-10-05 에 처음 낸 형태(`IRQ_MASK[1]` reset 1)가 하위 호환이 아님을 짚고, 미배정
`0x32C` FAULT_IRQ_EN(reset 0) 안으로 고쳤다(`docs/hiu_abi.md` §4).

## 9. 토폴로지 · WT64v1 · wave

- **WT64v1** — WaveTensor 64-bit Dataflow ISA, version 1. 데이터플로 명령어 집합과
  실행 기계의 규약이다 (`00-preface.typ:80-81`).
- **토큰** — 64-bit 페이로드 + 80-bit 태그 (`00-preface.typ:90-91`).
- **PE** — 연산을 수행하는 단위이며 이종이다(참조 구현 실측은 범용·행렬·나눗셈
  셋, `02-fabric-alu.typ:40-62` 측정 트랙). **Cluster** — PE 그리드 한 장 + 공유
  디코더 + 결과 뱅크. 공유 자원이 존재하는 최소 단위다. **Pod** — Cluster 그리드
  한 장. 현행 실측 형상의 최상위다 (`02-fabric-alu.typ:10-20`).
- **형상** — 그리드 크기는 구현 파라미터이며 각각 최대 4×4 다. 기본 형상은 2×2
  Cluster × 2×2 PE = **16 PE**, ISA 상한은 **256 PE** 다 (`02-fabric-alu.typ:22-27`,
  `00-preface.typ:108-110`). 형상은 명령 인코딩에 나타나지 않는다(형상 독립성,
  INV-T1/T2).
- **Global Grid / 다중 Pod** — 설계 의도로만 존재한다. 다중 Pod 구성은 2026-07-12 에
  철회됐다 (`02-fabric-alu.typ:29-32`, `a-capacity.typ:44-48`). 참조 구현의
  상호연결은 NoC 가 아니라 브로드캐스트 · valid 디먹스 · OR 병합이다(실측,
  `02-fabric-alu.typ:129-156`, `b-gaps.typ:30-32`).
- **wave 번호** — 80-bit 태그 안의 32-bit **불투명 식별자**다. 값을 짓고 올리는
  것은 호스트다. 기계는 등가 비교·보존 외에는 해석하지 않으며, 증가도 기계가 하지
  않는다 (`01-isa-asm.typ:822-837`, `:1018-1021`). wave 번호는 **순서 기전이 아니고
  아무것도 게이트하지 않는다** (`04-ext-payload.typ:682-683`).
  ⇒ Y4 의 「wave-aligned preemption」은 Y4 스케줄러의 정책 이름일 뿐이고, 장치
  측 근거는 §4 드레인이다.
- WT64v1 ISA(opcode 표 등)는 Y4 의 ABI 경계가 **아니다**(§10).

## 10. 장치 ↔ Y4 ABI 경계

Y4 가 직접 의존하는 WaveTensor 표면은 **구성 표면(§2) 하나**다. 정본은 이
경계를 이렇게 규정한다: 구성 표면의 계약은 정본 단독으로 동결할 수 없고, *동결에는
양쪽 합의가 필요하다* (`03-hiu.typ:1608-1616`, §3.10). 그 합의의 Y4 측 문서가
`docs/hiu_abi.md` 다.

1. **구성 표면 레지스터 맵** (E.1) — §2 표. 그중 Y4 가 직접 쓰는 것은 변환(§3),
   임대 회전·마스킹(§4–§5), 소유권(§6), fault·통지(§8)다.
2. **판 워드 `0xFFC` HIU_ABI_VERSION** (RO) — 드라이버가 가장 먼저 읽는 워드다.
   **합의 전 값은 0 이고, 판 0 은 물려받은 `0x000`–`0x11F` 에 어떤 레이아웃도
   약속하지 않는다.** 판 값과 필드 분할은 합의가 정하고, 그 내용은 3.10 v1.0 묶음이 정했다 —
   `[31:16]` major · `[15:0]` minor, v1.0 = `0x0001_0000`, major 변경은 비호환이다. 비0 값은 양측
   sign-off 뒤 별도 커밋에서만 장치에 들어가므로 그때까지 값은 0 이다. 그리고 「그 커밋은 `0xF0C` FP_SHAPE
   의 배선과 함께이거나 그 뒤다」 — 판 값을 내는 장치는 FP_SHAPE 의 부호화 번호와 실제 $P$ · stepMax 도
   알려야 하기 때문이다 (`03-hiu.typ:1630-1638` · `:1650-1655`, `e-defined.typ:504-505`, `docs/hiu_abi.md`
   §0 · §1.4). 순서는 sign-off → FP_SHAPE 배선 RTL 파도 → 판 값 커밋이다(2026-10-18 사용자 결정 U3).
3. **§3.10 합의 입력** — 함께 올렸던 다섯(물려받은 구역·판 워드의 처분, E.1.3 소비 회로 없는
   RW 워드의 쓰기 거절, 소거 구간 중 읽기, 바이트 폭 레지스터의 워드 정렬 재배치)은 3.10 v1.0
   묶음(2026-10-09)이 닫았다. 묶음 전체의 *동결*은 양측 sign-off 가 남았다 (`03-hiu.typ:1640-1647`).
   - **호스트 ABI 경계 합의 대기 아홉** (정본 B.5 요약): 장치 쪽에서 닫을 수 없는 넷 — 「링의
     거처·E.8 선택자 오프셋·링 크기 인코딩·개시 wave 태그의 원천」 — 과, v1.0 묶음이 모양까지
     합의하고 v1.x 로 넘긴 다섯 — 「키·논스 바이트 소거 · fault 의 인터럽트 경로 · 사상표 소거
     완료 비트 · 소유권 표 용량 워드 · 파티션별 변환 펜스」 (`b-gaps.typ:2183-2186`).
   - **동결 대기:** 에포크 폭 4b (`b-gaps.typ:1130-1131`), 태그 배치 전체 (`b-gaps.typ:975-976`).
     프레임 폭은 3.10 v1.0 묶음이 32b 로 정했고, 변환 항목 비트 배치는 형상 비노출 표면으로 호스트
     계약에서 내려와 안쪽 저장의 일이 됐다 (`e-defined.typ:1439-1441`, `:806-812`).

**WT64v1 ISA 자체**(opcode 표 등)는 Y4 의 ABI 경계가 **아니다**. ISA 는 게스트
SDK 가 가속기와 직접 말할 때 의미가 있고, Y4 는 capability 검증과 메모리
mapping 만 책임진다.

> 합의 상태 표)을 반영했다. v0 의 legacy 레지스터 표(`0x000`–`0x110`)는 그 문서 §8 이력으로
> 내려갔다. 재구현 장치에는 그 워드들이 *없고*, 쓰면 `FAULT_STATUS[6]` 이 선다(정본
> §3.10 처분, WaveTensor 판정 HP-1).

## 11. 「Y4 ABI」의 중의성 — 네 표면의 분간

§10 은 *Y4 가 무엇에 의존하는가*(하향)를 정한다.  그것만으로는
**게스트 SDK / 드라이버가 Y4 에게 말하는 표면**(상향)이 무엇인지 답하지
않는다.  「Y4 ABI」라는 말이 실제로는 넷을 가리키므로 아래로 가른다.

| # | 표면 | 방향 | 정의 위치 | 상태 |
|---|---|---|---|---|
| A | Y4 ↔ HIU 구성 표면 (MMIO 레지스터 맵 + 시간 계약) | Y4(호스트) **→** 가속기 | `docs/hiu_abi.md` (상대편: WaveTensor 정본 E.1 · §3.10) | **v1.0-rc3 — 동결 후보** (WaveTensor 정본 `f6bc4df` — D1–D4 답 · rc2 대조 답 반영), C1 · C2 대기(Y4 sign-off 차단 — C1 동결 sha 서면 지명 · C2 `0xF08` `[1]` 읽기 순서 한 문장) 뒤 양측 sign-off.  `0xFFC` 합의 전 값 = 0 (판 0 = 「약속 없음」, §10) — 비0 판 값 `0x0001_0000` 은 sign-off 뒤, FP_SHAPE 배선과 함께이거나 그 뒤의 별도 커밋 |
| B | 게스트 ↔ 하이퍼바이저 hypercall | 게스트 **→** Y4-VMM | **`docs/y4_abi.md` §2** (v0 draft) | 정의됨 (2026-09-14).  core VMM 은 워크스페이스 안, `y4-hypercall` repo 는 §5.3 재정의 후 사용자 CLI 전용(디스크 미존재) |
| C | seL4 fork raw-SVM syscall (D1a) | root task **→** 커널 | 전용 절 없음 — `docs/vmm_arch.md` §1 (`CONFIG_Y4_AMDV` raw-SVM cap) + §4 매핑 표에 `ObjectType_SVM*` / `Create` / `Configure` / `RebaseTsc` / `Migrate` / `ChangeParent` 로 흩어져 있다 | `phase_plan.md` Phase C 차단 의존 5 = (열림) |
| D | lease capability 스키마 | Y4 내부 (in-process API) | `docs/lease_capability.md` §3.1 | v0.8 draft.  `LeaseManager.acquire()` 는 **Rust 시그니처**이지 ABI 가 아니다 — §3.2 는 게스트의 cap 취득 경로가 IPC/hypercall/MMIO trap 중 무엇인지 명시하지 않는다 |
| — | WT64v1 ISA | 게스트 SDK **→** 가속기 | WaveTensor 정본 `G/chapters/01-isa-asm.typ` | §10 대로 **Y4 의 ABI 경계 아님** |

**「Y4용 드라이버 / SDK」가 실제로 부르는 면이 위 넷 중 무엇인지는
미결이다 — 이 문서는 그것을 정하지 않는다.**  방침(2026-08-30)은
「구체적인 Y4 ABI」라고만 적었고 어느 표면인지 말하지 않았다.  후보는
최소 셋이다: ⒜ B 단독 ⒝ B + D (게스트가 lease 를 취득하고 그 권한으로
HIU MMIO 를 두드리는 규약) ⒞ B·C·D 전부.  **어느 것이냐가 블로커의
크기를 정하므로 사람이 정한다.**

**해소 (2026-09-14, 사용자 지시):** 「Y4용 드라이버/SDK」가 부르는 면 =
**게스트-대면**(B + D + 가상 디바이스 C-service)로 확정.  스펙의 집 =
**`docs/y4_abi.md`**(v0 draft — hypercall + capability + 가상 디바이스 세 표면).
위 「사람이 정한다」는 이로써 답해졌고, 남은 것은 그 문서의 **v1.0 frozen**
(`y4_abi.md` §7)뿐이다.

> 미결 등재처 (네 저장소가 같은 질문을 열어 두고 있었다):
> `.claude-memories/y4_toolchain_and_abi_policy.md` §6-4 ·
> wavetensor-sdk `docs/architecture.md` §11 [Q14] ·
> wavetensor-drivers `docs/platforms.md` §7 ⑺ ·
> WaveTensor `.claude-memos/dev_platform_axis.md` §6.

따라서: **A 를 「그 ABI」로 읽지 말 것.**  hiu_abi.md 는 방향이 반대이고,
그 문서에 게스트 ABI 나 툴체인 사항을 덧쓰면 §0 동결 정책(Y4 + WaveTensor
양측 sign-off)이 오염된다.

B 의 신설은 사용자 방침(2026-08-30)이 「Y4용 드라이버 및 SDK 개발」의
**선행 조건**으로 지목한 항목이다 — `docs/phase_plan.md` Phase C 절
말미의 **「게스트 ↔ 하이퍼바이저 ABI spec 은 위 목록에 없다」** 주석에
등재.  그 선행 조건은 **y4-drivers 진입**에 걸리는 것이지 Phase C 자체의
차단 의존이 아니다 (방침은 Phase C 를 막는다고 말하지 않았다).

spec 의 소재지는 **해소됐다**: ⒜ `Y4/docs/` 안 신설 — `docs/y4_abi.md`
(2026-09-14).  ⒝ `y4-hypercall` 개설 · ⒞ 다른 sibling repo 갈래는 택하지 않았다.

## 12. legacy 용어 대응표 (옛 판 §1–§10 → 정본)

Y4 의 다른 문서(`hiu_abi.md`, `lease_capability.md`, `architecture.md` 등)에 남은
옛 용어를 읽을 때 쓴다. `hiu_abi.md` · `lease_capability.md` · `architecture.md` 본문은 2026-10-02 에
정본 기준(H1–H4 · HP-1..7 반영)으로 정정됐고, 지금은 `hiu_abi.md` v1.0-rc3 · `lease_capability.md` v0.8 이다(§11). 이 표는 이력·다른 문서용이다.

| 옛 용어 (legacy 기준) | 정본 대응물 | 비고 |
|---|---|---|
| partitioned TLB (4 × 16) | 변환 저장 + 형상 비노출 변환 항목 표면 `0xC00` (§3) | 4×16 은 측정값(참조 형상). 규범은 인코딩 상한 파티션 ≤ 4 뿐이고, 파티션당 용량은 `0xFF8` HIU_SHAPE 가 정보로 알린다 |
| shadow region (16 슬롯, identity-map) | **없음.** 호스트가 기입하는 변환 항목(§3)이 그 자리 | 정본·부록 E 에 「shadow」 0건 |
