# Y4 ↔ HIU ABI (v0.2 — draft, not frozen)

이 문서는 Y4 가 WaveTensor 가속기의 HIU(호스트 인터페이스)에 의존하는
**유일한 ABI 표면**, 즉 HIU 구성 표면(MMIO)의 **Y4 측 문서**다.
상대편은 WaveTensor 정본 `docs/wt64v1-architecture-guide/` 부록 E(E.1
레지스터 맵 · E.2 변환 항목 · E.3 미적중 채움 · E.6 완료 통지 · E.7 페이지
소유권 · E.9 마스크 키와 논스)와 §3.10 「호스트 ABI 경계」다.

- 용어와 정본 인용: [`./glossary.md`](./glossary.md) (§2–§10).
- 이 문서의 `G/…:줄` 인용은 WaveTensor 커밋 `645bed0` 기준이다.
- 이 문서가 동결(`v1.0 frozen`)되어야 Y4 의 mock-HIU(`hiu/mock/`)와 lease
  capability 런타임(Phase C)이 시작될 수 있다.

> **v0.1 → v0.2 (2026-10-05).** WaveTensor 의 §3.10 v1.0 동결 묶음 제안(`645bed0`)에 대한
> Y4 확정 답(`.local-replies-to/WaveTensor/2026-10-05-reply-s310.md`)을 반영했다.
> 이 문서는 **Y4 가 v1.0 으로 제안하는 표면**을 적는다. 항목마다 지위를 단다:
> - **정본** — `645bed0` 정본에 이미 있다.
> - **WT 제안** — WaveTensor 가 제안했고 Y4 가 동의(또는 조건부 동의)했다. 정본 반영 대기.
> - **Y4 제안** — Y4 가 제안했고 WaveTensor 의 응답 대기.
> - **Y4 제안 · WT 동의** — Y4 가 제안했고 WaveTensor 가 동의했다. 정본 반영 대기.
>
> 합의(§3.10 양측 sign-off) 전에는 어느 쪽 제안의 *새 표면*(`0xE14` · `0xFF8` · 형상 비노출
> `0xC00` 창 · 비0 판 값)도 장치에 없다. 오늘 RTL 의 동작을 그대로 규범으로 굳히자는
> 항목(`0xF84` 전체 거절 · 하류 HI 버스 정지 · `[12]` 강등 · 소거 구간 읽기)은 장치에 있지만
> 아직 정본 규범이 아니다.

> **v0 → v0.1 (2026-10-02).** v0(2026-05)의 레지스터 표는 WaveTensor legacy
> 참조 구현을 기준으로 했다. 재구현 장치에는 그 워드들이 없다(HP-1). v0.1 은
> 정본 부록 E 에 맞춰 다시 썼고, 옛 표는 §8 이력으로 내렸다.

## 0. 동결 정책

- 동결은 **Y4 측 + WaveTensor 측 양쪽 합의**로만 일어난다. 정본 §3.10 은 「동결에는
  양쪽 합의가 필요하다 … 한쪽만 바꾸면 조용히 어긋난다」고 적는다
  (`G/chapters/03-hiu.typ:1324-1330`). Y4 는 일방 변경을 무효로 취급한다(Y4 정책).
- **판 워드는 `(major << 16) | minor` 로 한다**(Y4 제안 · WT 동의 — 정본 반영 대기, §1.4).
- **minor / major 기준** (원칙: WT 제안 · Y4 동의 / 행동 기준 문면: Y4 제안 — 2026-10-05 답 Q4):
  - minor 증가 = 같은 major 의 v1.0 적합 드라이버(§1.2.1 의무를 지키는 드라이버)가 낼
    수 있는 모든 접근 순서에서, 그 드라이버가 *의무대로 해석한 결과*와 v1.0 의 격리 ·
    fail-closed 성질이 그대로인 변경. 적합 드라이버의 접근 순서에서는 일어날 수 없는
    사건의 보고만 달라지는 변경도 minor 다. 그 밖은 major.
  - minor 의 예:
    - (a) 미배정 오프셋에 새 워드를 두되 reset 값이나 0 이 이전 동작을 재현하는 경우.
      정본의 「*레지스터 추가는 하위 호환 형태*가 된다」(`03-hiu.typ:707-710`)가 이것이다.
    - (b) 엄격 예약 비트를 수락으로 넓히되 0 이 v1.0 동작을 내는 경우. 또는 v1.0
      드라이버가 쓰지 않는 워드(E.1.3 「소비 회로가 없는 RW 워드」)를 수락으로 넓히는 경우.
    - (c) v1.0 에 없는 기능을 쓸 때만 나오는 새 완료 kind(`e-defined.typ:1082-1087`), 또는
      호스트가 무시하는 여백 필드(`:1141-1147`).
    - (d) FAULT_STATUS `[31:19]` 의 새 원천 비트. 단 v1.0 적합 드라이버의 접근 순서에서는
      서지 않는 원천 — v1.x 기능을 켤 때만 사는 원천이거나 v1.0 에서도 이미 정본 위반인
      사건 — 에 한한다. 적합 순서에서도 설 수 있는 원천은 major 다(v1.0 드라이버가 미지
      비트로 fail-closed 해 정상 운용을 잃는다). 기존 비트에 새 원천을 접는 것도 뜻 변경이라
      major 다.
    - (e) `0xC00` 구역 `+0x0C` VPN 상위를 수락으로 여는 VA 확장(§1.3 변환).
  - 언제나 major: 기존 필드의 위치 · 폭 · 뜻 변경 · 새 필수 호스트 단계 · 0/reset 값이
    v1.0 과 다른 새 필드 · v1.0 적합 드라이버가 낼 수 있는 접근에서의 수락 → 거절 ·
    비트 제거 · `MASK_STATUS` `[8]`/`[9]` 의 뜻 변경 · 변환 항목 표면 배치 변경.
  - 판의 일이 아닌 것: 변환 저장의 형상(파티션당 용량 · 연관도 · 교체 정책) 변경
    (§1.3 변환 결과 규범 (g) · (h)).
  - 판 보고: minor 는 누적이다. 적합성을 되돌리는 RTL 수정은 번호를 바꾸지 않는다.
- **비0 판 값은 양측 sign-off 뒤에만 장치에 들어간다**(Y4 제안 — 2026-10-05 답 §5).
  순서: 사용자 확정 → 정본 spec 커밋(Y4 가 diff 대조) → WaveTensor 선-formal · RTL ·
  후-formal 파도(이 동안 `0xFFC` = 0) → 이 문서 `v1.0 frozen` + 양측 sign-off → 판 값
  `0x0001_0000` 커밋. 파도에서 정본 문면 수정이 나오면 1–2 단계(사용자 확정 · 정본 spec 커밋)로 돌아간다.
- v0.x 는 draft 다. 누구든 바꿀 수 있지만 커밋 메시지에 `hiu-abi: <요지>` 접두가 필수다.
- 정본 자신은 pre-stable 이고 `T_stable` 이 미정이다(`G/chapters/00-preface.typ:36-54`).
  이 문서는 정본 변경을 따라간다.

> **현재 상태:** v0.2 — draft. 양측 합의 전. `0xFFC` 장치 값 = 0(판 0, §1.4).

## 1. 구성 표면 (호스트가 보는 4 KiB 페이지)

구성 표면은 **4 KiB 한 페이지**의 32-bit 워드 맵이다. 페이지를 호스트 버스(PCIe BAR
등)의 어디에 두는지, 워드의 바이트 순서를 버스에 어떻게 싣는지는 보드·어댑터 층의
일이며 이 ABI 가 정하지 않는다(P3, `docs/hw_mechanism_abstraction.md`; 정본도 구성
표면의 바이트 순서를 정하지 않는다).

**한 페이지는 쪼갤 수 없다** — 게스트에게 어느 구역이든 직접 MMIO 를 주면 같은
페이지의 변환·마스킹 구역도 함께 닿는다. 그래서 **게스트는 이 페이지에 직접 닿지
않고, 모든 구역을 Y4 가 capability 검증 뒤 대행한다**(Y4 정책 — 아래 「Y4 사용」
열의 분류도 Y4 의 선택이다).

### 1.1 영역 배치 (정본 E.1, `G/appendix/e-defined.typ:44-57`)

| 범위 | 내용 | Y4 사용 |
|---|---|---|
| `0x000`–`0x11F` | **물려받은 구역** — 뜻은 §3.10 합의 대상. 합의 전 처분: 쓰기 거절 + `FAULT_STATUS[6]`, 읽기 0 | **사용 안 함** (§5.2) |
| `0x120`–`0x1FF` | 예약 | — |
| `0x200`–`0x2FF` | 페이지 소유권 표 (E.7) | ✔ §1.3 |
| `0x300`–`0x37F` | 완료 방향 — 완료 링 · 완료 통지 · 드레인 관측면 | ✔ §1.3 |
| `0x380`–`0x3FF` | 명령 방향 — 명령 링 (E.5) | 소비 회로 착지 후 (§5.3) |
| `0x400`–`0x7FF` | LNID 소유 표 (256 × 4 B) | Y4 대행 (게스트 SDK 요청 — 요청 형식은 `y4_abi.md`) |
| `0x800`–`0xBFF` | LBID 사상표 (256 × 4 B) | Y4 대행 (같음) |
| `0xC00`–`0xDFF` | 변환 항목 창 — 파티션별 128 B (`addr[8:7]` = 파티션). 창 안의 배치는 §1.3 변환 (Y4 제안: 형상 비노출 표면) | ✔ §1.3 |
| `0xE00`–`0xE7F` | 변환 저장소 제어 — flush · 미적중 관측 · 결속 | ✔ §1.3 |
| `0xE80`–`0xEFF` | 마스킹 — 키 · 논스 · 재키잉 | ✔ §1.3 |
| `0xF00`–`0xF3F` | step 프로그램 적재 | Y4 대행 (같음) |
| `0xF40`–`0xF7F` | 재조립 문맥 소거 | ✔ §1.3 — 드레인에 필요 (§2.3) |
| `0xF80`–`0xFBF` | 장치 전역 fault | ✔ §1.3 |
| `0xFC0`–`0xFFF` | 장치 식별 — `0xFF8` HIU_SHAPE(자리 WT 제안 · 필드 Y4 제안) · `0xFFC` ABI 판 | ✔ §1.4 |

### 1.2 페이지 전역 접근 규칙

| 대상 | 쓰기 | 읽기 | 근거 |
|---|---|---|---|
| 기입 단위 | 워드 하나. 주소 하위 두 비트 ≠ 0 인 쓰기는 페이지 어디서든 거절 + `[6]` | 비정렬 읽기 0, fault 없음 | `03-hiu.typ:745-754` (HP-4) |
| WO 워드 | 수락 | **0** — 되읽기를 주지 않는다. fault 없음 | `e-defined.typ:198-201` (H1-1) |
| RO 워드 | 거절 + loud fault | 값 | `e-defined.typ:202-204` |
| 워드 안 예약 비트 | 비0 기입은 거절 + loud fault (엄격) | 0 | `e-defined.typ:188-190` |
| 표에 없는 오프셋 | 무시 | 0 | `e-defined.typ:205-206` |
| 물려받은 `0x000`–`0x11F` | 거절 + `[6]` | 0, fault 없음 | `03-hiu.typ:1337-1343` (HP-1) |
| 소비 회로 없는 RW 워드 (`0x300`/`0x304` · `0x380`/`0x384` · `0x388` SQ_SIZE · `0x390` SQ_TAIL) | 거절 + `[6]`. **잠정** — 회로가 서면 수락으로 넓힌다 | 0 | `e-defined.typ:743` (HP-3) |

#### 1.2.1 v1.0 드라이버 의무 (Y4 제안 — §0 minor 기준의 전제)

Y4 는 자기 드라이버에 다음을 의무로 둔다. 정본 규칙으로도 들일지는 WaveTensor 판단이다.
MMIO 쪽에는 「RO 예약 비트를 호스트가 무시한다」는 정본 의무가 아직 없다(완료
디스크립터 `e-defined.typ:1144` 「*호스트는 예약을 무시한다.*」에만 있다).

- 미배정 오프셋에 쓰지 않는다.
- E.1.3 의 소비 회로가 없는 RW 워드(링 base 넷 · `SQ_SIZE` · `SQ_TAIL`)에는 쓰지 않는다.
  `CQ_SIZE` 에는 현재 값만 쓴다. 그래서 v1.0 Y4 부팅은 「E.5 식 초기화」를 하지 않는다
  (`03-hiu.typ:1352-1353` 「E.5 식 초기화는 부팅마다 `[6]` 을 받는다」).
- RW 구성 워드는 읽고-고치고-쓰기(RMW)로 갱신한다. 되읽은 값의 v1.0 미정의 비트는
  그대로 되쓴다.
- WO 워드와 발화 워드의 예약 비트에는 0 을 쓴다. 단 `0xF84` FAULT_CLEAR 에는 `0xF80` 에서
  읽은 값을 그대로 쓴다.
- RO 읽기는 정의된 비트로 마스크해서 해석한다.
- 거절 + `[6]` 을 기능 탐침으로 쓰지 않는다.
- 모르는 FAULT 비트는 fail-closed 로 처리하고, 읽은 값 그대로 W1C 로 되쓴다(고정 마스크를 쓰지 않는다).
- 매 `MASK_REKEY` 전에 그 파티션의 키와 논스를 새로 기입한다.
- `0xE0C` MISS_VPN_HI 가 0 이 아닌 미적중은 fail-closed 로 처리한다(v1.0 은 VA 44b 만 사상).
- (Q3 표면) 정지한 파티션에는 `0xE04[0]` = 1 인 동안 `0xE08` 이 보고한 VPN 만 커밋한다(§2.2).
- `0xE14` ACTIVE_PART 기입 뒤에는 `0xF80[6]` 과 되읽기로 수락을 확인한 뒤에만 재개한다.

### 1.3 Y4 가 쓰는 워드

**페이지 소유권** (정본 — E.1.2 `e-defined.typ:222-233`; 규범은 E.7 `:1370–`) — 상태는
호스트 소유 / 장치 소유 둘뿐이다.

| 오프셋 | 이름 | 접근 | 뜻 |
|---|---|:-:|---|
| `0x200` | OWN_IDX | RW | 조회 대상 페이지 프레임 |
| `0x204` | OWN_STATUS | RO | `[0]` 1 = 장치 소유 |
| `0x208` | OWN_SET | WO | 장치로 이양할 프레임 — 기입이 곧 전이 |
| `0x20C` | OWN_CLR | WO | 호스트로 회수할 프레임 — 기입이 곧 전이 |

**완료 방향 (E.6)** (정본, `0x32C` 만 Y4 제안) — 통지는 **완료 링 항목이 유일한 수단**이다.

| 오프셋 | 이름 | 접근 | 비고 |
|---|---|:-:|---|
| `0x300`/`0x304` | CQ_BASE_LO/HI | RW | 오늘 완료 링은 장치 상주. 쓰기는 거절 + `[6]` (§1.2) |
| `0x308` | CQ_SIZE | RW | `[4:0]` log2(엔트리 수). 오늘 쓰기는 현재 값과 같으면 무동작 수락, 다르면 거절 + `[6]` (`e-defined.typ:725-726`) |
| `0x30C` | CQ_HEAD | RW | 호스트 소비 색인 |
| `0x310` | CQ_TAIL | RO | 장치 생산 색인 — **폴링 대상** |
| `0x320` | IRQ_STATUS | RO | `[0]` sticky 인터럽트 상태 · `[31:1]` RO 예약 = 0. (G2 Y4 제안: `[1]` fault 요약 — §4) |
| `0x324` | IRQ_MASK | RW | `[0]` 1 = 끔. **reset 1 — 기본은 폴링**. 갱신은 RMW (§1.2.1) |
| `0x328` | IRQ_CLEAR | WO | `[0]` 1 = 명시 해제 |
| `0x32C` | FAULT_IRQ_EN | RW | **Y4 제안 (G2, v1.x 후보)** — `[0]` 1 = fault IRQ 켬, reset 0 (§4) |
| `0x340`–`0x35C` | CQ_WINDOW[0..7] | RO | 32 B 완료 디스크립터 창 |
| `0x360`–`0x374` | DRAIN[0..5] | RO | 드레인 정의역 여섯의 진행 중 개수 |
| `0x378` | CQ_OCC | RO | 완료 링 점유 |
| `0x37C` | DRAIN_ALLZERO | RO | `[0]` DRAIN 여섯 + `0x378` CQ_OCC 가 전부 0 (단일 읽기 스냅샷, `e-defined.typ:270-271`) |

**변환 — 항목 창 `0xC00`** (**Y4 제안 — 형상 비노출 표면**, 2026-10-05 답 Q3)

Y4 는 「파티션당 색인 16 고정」(WT 제안)에 동의하지 않았다. 고정하면 폼팩터마다 형상을
달리할 수 없고, 파티션당 64 KiB 의 변환 도달 범위가 ABI 에 박히며, 직접 사상이라는 장치
안쪽 방식이 바깥 계약이 된다. 대신 호스트는 (VPN, 프레임, 권한)만 기입하고 장치 안 어느
칸에 둘지는 장치가 정하는 표면을 제안했다.

| 오프셋 (파티션 기저 `0xC00 + (p≪7)` +) | 이름 | 접근 | 필드 |
|---|---|:-:|---|
| `+0x00` | XLATE_ENTRY_VPN | WO | `[31:0]` 가상 페이지 번호(VA 44b). 스테이징 — 열의 첫 워드 |

결과 규범 (안쪽 방식은 자유, 결과만 건다):
- (a) V=1 커밋 뒤 같은 (파티션, VPN) 조회는 그 프레임 · 권한으로 적중하거나, (h) 의 축출로
  밀려났으면 미적중이다. 같은 (파티션, VPN) 에 두 항목이 동시에 적중하지 않는다(뒤 커밋이
  대체 — HIU-4 `03-hiu.typ:1731-1734` 를 좁힘).
- (b) **V=0 커밋 뒤 같은 (파티션, VPN) 조회는 반드시 미적중이다**(단일 항목 무효화 —
  사상 철회의 동기 보장). 상주하지 않는 VPN 의 V=0 커밋은 무동작이다.
- (c) 축출은 같은 파티션 안에서만 일어난다(3.6.1 결과 3, `03-hiu.typ:582-584`).
- (d) 미적중 정지는 정지한 요청의 (파티션, VPN) 에 대한 V=1 커밋(거부 채움 포함)이
  수락되면 풀리고, **풀린 그 요청은 그 커밋 항목으로 판정된다** — 그 요청이 조회 지점을
  떠나기 전에 다른 커밋이 그 항목을 밀어내도 다시 미적중하지 않는다(`03-hiu.typ:637`
  「진행 중 채움의 바이패스」가 주는 성질을 결과로 건다). E.3 2항 「호스트가 항목을
  기입하면 정지가 풀린다」(`e-defined.typ:873`)의 「항목 기입」을 이렇게 좁힌다.
- (e) `0xE00` flush 는 그 파티션의 항목을 전부 무효로 한다.
- (f) 스테이징은 장치에 하나다. 열은 VPN → FRAME → COMMIT 이다.
  - VPN 기입은 기입 주소의 파티션을 래치하고 FRAME 스테이징의 유효를 내린다(묵은
    프레임이 새 VPN 에 묶이지 않게).
  - FRAME 은 래치 파티션과 같은 기저에서만 수락한다(다르면 거절 + `[6]` · 스테이징 불변).
  - V=1 COMMIT 은 마지막 VPN 뒤에 수락된 FRAME 을 요구한다. V=0 COMMIT 은 VPN 만 요구한다(프레임 무관).
  - 다음 COMMIT 은 거절 + `[6]` 이고 아무것도 움직이지 않는다: 래치와 다른 파티션 기저 ·
    VPN 없음 · FRAME 없는 V=1 · `[27:0]` 비0.
  - 커밋은 스테이징을 소진하지 않는다 — 같은 짝의 재커밋과 V=0 되풀이는 매번 커밋된다.
    없는 파티션 기저로의 기입은 거절 + `[6]` 이고 스테이징을 움직이지 않는다
    (`e-defined.typ:423-425`). 래치 파티션의 수락된 flush 가 두 스테이징 유효를 내린다.
  - 하류 슬롯이 찬 동안의 *적법한* COMMIT 은 버스를 정지시킨다. 정지 중에는 효과가 없고,
    슬롯이 비면 같은 기입이 수락되어 단일 에지로 커밋된다 — 거절도 드롭도 아니다(오늘 HI 의
    측정 트랙 사실, `03-hiu.typ:1270`). 거절될 기입(위 거절 사유)은 기다리지 않고 곧바로
    거절 + `[6]` 이다. 정지는 장치 의무로서 유계 시간 안에 풀려야 하고, 호스트 조치에 기대지
    않으며 다른 정지(미적중 정지 · 부팅 소거 구간)와도 독립이다(Y4 요청 — Q1 (a)–(c)).
    단일 접근의 정지는 Y4 의 폴링 타임아웃이 다룰 수 있는 대기가 아니다.
- (g) 파티션당 용량 · 연관도 · 교체 정책은 형상이고 장치 안쪽의 일이다. `0xFF8` HIU_SHAPE 가
  용량을 *정보로* 알린다(§1.4). 정합성은 용량에 기대지 않는다. 교체 결정과 교체 상태 갱신은
  커밋 경로에서만 일어나고, 조회는 저장과 교체 상태를 쓰지 않는다(5.3 상태열 동일성
  `05-security.typ:232` · SEC-2 `:487-492`). 커밋 처리(희생 항목 선택 · 태그 탐색 포함)는 조회
  경로에 정지나 ready 를 만들지 않는다. 교체 상태는 파티션별이고 다른 파티션의 상태에 기대지
  않는다.
- (h) **진행 보장** — 축출은 같은 파티션에 대한 호스트 COMMIT 과 flush 의 결과로만
  일어난다. 시간 경과 · 조회 · 다른 파티션 활동 · 배경 작업에 의한 자발 축출은 없다. 그래서
  (d) 와 함께 드라이버는 미적중 채움으로 언제나 수렴한다. 이 보장은 용량 · 연관도와 무관해야
  하고, 동시에 정지할 수 있는 조회 지점이 여럿인 형상은 그것을 구조로 지켜야 한다.

> **오늘 정본(`645bed0`)의 표면** — 위 제안이 합의되면 대체된다. `0xC00 + (p≪7) + (i≪3)`
> 의 LO(`[31:0]` 프레임, 스테이징 — 항목 번호 래치) · HI(`[31]` V · `[30:28]` 권한 ·
> `[27:0]` 태그) 직접 배열이다. 규범 상한은 파티션 ≤ 4 · 색인 ≤ 16 이고 4 × 16 은 측정
> 형상이다(`e-defined.typ:296-313` · `:791-803`). 실물 색인은 VPN 하위 비트다
> (`rtl/…/hiu/XlateStore.scala:248-249` @645bed0 `reqIdx = io.lookup.vpn(idxW - 1 downto 0)`).

| 그 밖 · 모르는 비트 | | 게스트 정책으로 넘기거나 fail-closed (§1.2.1) |

### 1.4 장치 식별 — `0xFFC` 판 · `0xFF8` 형상

**`0xFFC` HIU_ABI_VERSION (RO, 정본)**
- **합의 전 값은 0 이다. 판 0 은 물려받은 `0x000`–`0x11F` 에 어떤 레이아웃도
  약속하지 않는다**(`03-hiu.typ:1344-1350`, `e-defined.typ:504-505`; HP-2).
- 분할 `[31:16]` major · `[15:0]` minor, v1.0 = `0x0001_0000`(Y4 제안 · WT 동의 — 정본 반영
  대기). major 변경 = 비호환.
- Y4 는 major == 1 에만 결속한다. 판 0 이나 다른 major 이면 진행하지 않는다. 기능 x 는
  minor ≥ x 일 때만 쓴다.

**`0xFF8` HIU_SHAPE (RO — 자리: WT 제안 · Y4 동의 / 필드 배치: Y4 제안)**
- `[7:0]` 실재 파티션 수 · `[23:8]` 파티션당 항목 용량 · `[31:24]` RO 예약 = 0.
  - WT 제안은 `[15:8]` 파티션당 *색인 수* · `[31:16]` 예약이었다. Y4 는 형상 비노출 표면에
    맞춰 용량 필드로 바꾸자고 제안했다(용량이 256 이상일 수 있으므로 16b).
  - 두 필드 모두 개수 인코딩이다. 용량은 *각 실재 파티션에 보장되는* 항목 수다.
- 읽기 순서: `0xFFC` → `0xFF8`. Y4 는 major 1 일 때만 `0xFF8` 을 해석한다.
  - `[7:0]` = 0 은 「표면 없음」이다. 오늘 장치(판 0)에서 `0xFF8` 은 미배정이라 읽기 0 이고,
    §0 순서의 파도 뒤 판 0 장치에서는 값을 낼 수 있지만 Y4 가 판 0 에서 진행하지 않으므로
    해석되지 않는다.
  - `[7:0]` 이 1–4 밖이면 장치 결함으로 보고 fail-closed.
  - 용량은 *정보*다 — 사전 채움 양과 성능 계측에만 쓰고 정합성 판단에는 쓰지 않는다.
    0 이면 fail-closed.
- 쓰기는 거절 + `[6]` 이다(RO).

## 2. 시간 계약 · 순서 계약

### 2.1 요청 경로 — 상수 시간은 「경로 간 동일성」

- 요청은 여섯 단계를 지난다: 접수 → 고정 지연 → 변환표 조회 → 물리 주소 마스킹 →
  요청 실행 → 접근 승인. 적중 · 대체 · 미적중이 **같은 상태열**을 지난다
  (`03-hiu.typ:62-74`, `05-security.typ:230-232`).
- **절대 사이클 수는 ABI 가 아니다** (`05-security.typ:250-253`; H4-1). Y4 는 사이클
  수에 기대는 timed-read 를 쓰지 않는다.
- **요청의 발신자는 PE 쪽이다**(H4-6). **호스트 발행 DMA 단발 표면은 이 ABI 에 없다**
  (G4). Y4 의 데이터 경로는 페이지 소유권 이양(§1.3)과 링(E.5/E.6) 위에 선다.
- **요청 → 파티션 결속**은 `0xE14` ACTIVE_PART 가 정한다(WT 제안 · Y4 조건부 동의, §2.4). 패브릭의 일은 한 순간에
  한 임대(= ACTIVE_PART)의 것이다(`b-gaps.typ:1190-1192`). 오늘 실물은 최상위 내부 입력
  `hiuReq.part` 이고, ACTIVE_PART 가 그것을 MMIO 로 바꾼다.
- 마스킹 재키잉은 요청 경로 밖의 구성 사건이다(사이클 수는 ABI 아님).

### 2.2 미적중 채움 (E.3, HP-6)

1. 미적중은 **오류가 아니다**. 조회 단 전체가 배압으로 정지하고, `0xE04[1]` sticky 가
   선다. 이것은 FAULT_STATUS 에 접히지 않는다.
2. Y4 는 `0xE04` · `0xE08`/`0xE0C` 를 읽는다. 값은 정지 게이트 스냅샷이고, 읽어도
   아무것도 해제되지 않는다. 채움 파티션은 `0xE04[15:8]` 이 알린다.
3. Y4 가 그 파티션 창에 **`0xE08` 이 보고한 VPN 만** 커밋한다(VPN → FRAME → COMMIT, §1.3).
   **정지를 푸는 것은 그 VPN 의 V=1 커밋뿐이다**(결과 (d)).
4. 정지는 채움 직후 다시 설 수 있다(파이프 안의 다음 요청이 미적중이면 둘째 정지).
   그래서 Y4 는 `[1]` 이 아니라 `[0]` 을 보고 루프를 돈다.
5. 루프가 끝난 뒤 `0xE10` 으로 sticky 를 한 번 해제한다. **순서는 「항목 기입 → 해제」**
   다. 정지 중에 쓴 해제는 유실된다(fault 도 효과도 없음).

- **거부 채움:** 사상이 없는 VPN 의 정지는 V=1 · R=W=X=0 커밋으로 푼다 → 적중 → 승인
  거부 + `[4]`. 정리는 드레인 종류에 따라 다르다.
  - 임대 *회수*(회전 ⑴)의 드레인: ⑵ flush 와 짝짓는다.
  - 스케줄 *전환*(§2.4)의 드레인: 그 VPN 들의 V=0 무효화를 `DRAIN_ALLZERO` 관측 뒤, 재개
    전에 한 번에 한다. 루프 안에서 바로 무효화하면 아직 조회 지점을 떠나지 않은 요청이
    다시 정지할 수 있다. 파티션 flush 는 하지 않는다.
  - 거부 채움이 드레인을 완주시키려면 승인 거부된 요청이 드레인 정의역에 남지 않고
    퇴장해야 한다. Y4 는 이것을 정본에 적어 달라고 요청했다(§5.3).
- 장치는 타임아웃을 두지 않는다. **정지가 영구가 되지 않게 할 책임은 Y4 에 있다.**
  Y4 는 임대 메모리를 미리 핀(pre-pin)해 두어 언제나 채울 수 있게 한다. 사전 채움은
  상주를 보장하지 않으며 성능 힌트일 뿐이다(형상 비노출 표면).
- `0xC00` 기입 열(VPN → FRAME → COMMIT)을 쓰는 모든 경로 — 미적중 채움 · 회전 뒤 기입 ·
  회수 중 채움 — 는 **장치 전역 락 하나로 직렬화**한다(스테이징이 장치에 하나).

### 2.3 임대 회전 (정본 E.9 6항, `e-defined.typ:1538-1555`; H1-3 · H1-4)

⑴–⑷ 는 *그 파티션 p 에만* 걸린다(`e-defined.typ:1546` 「*하나*」). 전역 flush 는 없다.

1. **드레인 (정본 ⑴ = 3.7.2 드레인 의무; 기계에 드레인 모드는 없다).** p 가 ACTIVE_PART
   인지에 따라 갈린다(결속 전환이 언제나 §2.4 의 판정을 거친다는 전제).
   - **p == ACTIVE_PART** — 투입하는 것이 p 뿐이므로 「그 파티션에 대한 투입을 멈춘다」
     문면 그대로이고, 관측은 장치 전역 `DRAIN_ALLZERO` 로 한다.
     1. Y4 가 p 에 대한 **투입을 멈춘다** — 단일 capability invocation 안의 직렬화가 그
        수단이다.
     2. **드레인 루프** — `DRAIN_ALLZERO` 가 설 때까지 되풀이한다(유계):
        - 서 있는 미적중 정지를 채운다(§2.2 — 회수이므로 옛 임대 사상 또는 거부 채움).
          정지한 요청은 드레인 정의역 ①에 남아 `DRAIN_ALLZERO` 를 0 으로 붙잡는다
          (정본 B.5 「E.3 미적중 정지가 드레인 안에서 갖는 처분」 갈래 ⑴, `b-gaps.typ:1505-1529`).
        - 완료 링을 비운다(`0x30C` CQ_HEAD 전진, E.6 4항) — `DRAIN_ALLZERO` 는 CQ_OCC 를
          포함한다.
        - 마지막 조각을 잃은 재조립 문맥(`DRAIN[4]`)을 `0xF40` 태그 지정 소거로 닫는다
          (`03-hiu.typ:1057-1060`).
     3. 루프 뒤 `0xE10` 해제를 한 번 한다(「항목 기입 → 해제」).
     - 채우기 전에 `0xE04[15:8]` == p 와 `0xE0C` == 0 을 확인한다(어기면 fail-closed, §1.2.1).
   - **p ≠ ACTIVE_PART** — 결속이 p 를 떠날 때의 판정으로 ⑴ 은 이미 충족돼 있다. p 의
     일은 정의역 · 완료 큐 · 링 어디에도 없다. 살아 있는 임대의 투입은 멈추지 않는다.
     (이 분기는 3.7.2 의 드레인 의무를 「결속된 파티션의 구성 교체」로 좁히는 정본 개정을
     전제한다 — Y4 요청, §5.3.)
2. `0xE00` XLATE_FLUSH ← p. 그 파티션의 항목이 전부 무효가 된다. p 를 래치한 스테이징의
   유효도 내린다.
3. `0xEA0` MASK_PART ← p. `0xE80`–`0xE9C` 에 새 키 8 워드, `0xEA4`–`0xEB8` 에 새 논스
   6 워드를 기입한다. 이 열(⑶ → ⑷)은 장치 전역으로 직렬화한다(창이 하나).
4. `0xEC0[9]`(재키잉 수락 가능)이 설 때까지 기다린 뒤 `0xEBC` MASK_REKEY ← p.
   - 완료 관측: **`0xEC0[8]`(엔진 busy)이 내려갈 때까지 기다린 뒤**, 그 파티션 준비 비트와
     `0xF80` 의 `[6]` · `[12]` · `[13]` 을 확인한다. 정본 ⑷ 「그 파티션 비트가 설 때까지
     기다린다」(`e-defined.typ:1543-1544`)는 `[13]` 이면 끝나지 않고 `[12]` 를 놓치므로,
     Y4 는 이 관측을 쓰고 정본 개정을 요청했다(§5.3).
   - 이 관측은 수락된 `MASK_REKEY` 뒤의 읽기가 완료 전까지 `[8]` = 1 을 본다는 전제에 선다.
     정본(`e-defined.typ:345-347`)은 이것을 적지 않는다(오늘 RTL 은 수락 다음 사이클부터
     busy). Y4 는 ⑷ 개정 요청에 이 문면을 함께 넣는다.
   - 처분: ⑶ 진입 전에 `0xF80` 의 `[6]` · `[12]` · `[13]` 이 0 이어야 한다 — sticky 라서, 서
     있으면 앞 사건으로 처분하고 `0xF84` 로 해제한 뒤 진입한다. 준비 = 1 ∧ `[6]` · `[12]` ·
     `[13]` = 0 일 때만 성공. 준비 = 0 · `[13]` · `[9]`/`[8]` 대기 시간 초과면 `0xF84` 로 해제한 뒤
     ⑶ 부터 유계 재시도하고, 재시도가 소진되면 그 파티션을 격리한다. 재시도의 ⑶ 은 같은 키와
     *새* 논스(`NonceAllocator.next()`)를 기입한다 — 쌍 유일성(§3.2)이 재시도 경로에도 서게
     한다. `[12]` 면 재시도하지 않고(같은 논스로 ⑶ 을 다시 하면 같은 `[12]` 가 결정론적으로
     다시 선다) §2.6 으로 원인을 귀속한다. `[6]` 이면 Y4 결함(값 오류).
   - 모든 대기는 유계다. 드레인 시간 초과는 flush 로 진행하지 않는다(P10 — 장치는 타임아웃을
     두지 않는다). p == ACTIVE_PART 회전의 드레인 시간 초과는 결속을 옮길 길이 없으므로
     §2.4 와 같이 **장치 전체 격리 + 장치 reset** 이다.

- **Y4 측 선택:** 새 임대의 항목 기입(`0xC00`)은 ⑷ 뒤에 한다. ⑵ 뒤 첫 기입은 새 열의
  처음(VPN)부터다 — flush 가 스테이징을 비우기 때문이다.
- 순서를 어긴 구간의 요청은 **정지되지 않고 통과**하며, `[11]` 이 사후에 알린다
  (`e-defined.typ:1551-1555`). 장치 자체는 fail-closed 가 아니라 loud 다 — fail-closed 는
  Y4 정책(P10)이다.
- `DRAIN_ALLZERO = 1` 은 「드레인 정의역 여섯 + 완료 큐가 비었다」이지 「장치 전체가
  유휴」가 아니다. 정의역 밖 실행 주체를 두는 확장이 들어오면 다시 따져야 한다(정본
  B.5 조건부, `b-gaps.typ:1979-2004`).
- 회전마다 에포크를 올리는 호스트 의무(규약 미정, B.5)는 §5.3-6 데이터 경로 묶음에서
  정한다.

### 2.4 임대 전환 — 결속 교체 (WT 제안 `0xE14` · Y4 조건)

스케줄러가 패브릭을 다른 살아 있는 임대에게 넘길 때다. flush · 재키잉은 없다.

1. 지금 결속된 임대에 대한 투입을 멈춘다.
2. 드레인 루프(§2.3 ⑴-2 와 같음). 미적중 정지는 *살아 있는 임대의 실제 사상*으로 채운다.
   사상이 없는 VPN 은 거부 채움으로 풀고, `DRAIN_ALLZERO` 관측 뒤 그 VPN 들의 V=0 무효화를
   한 번에 한 다음 `0xE10` 해제를 한 번 한다(「항목 기입 → 해제」, §2.2).
3. `0xF80[6]` = 0 을 확인한다(서 있으면 앞 사건으로 처분 · 해제). 그 뒤 `0xE14` ← 새 파티션.
   `0xF80[6]` 과 되읽기로 수락을 확인한다.
   - 거절(`[6]`)이면 Y4 결함(투입 정지 실패 또는 드레인 오판)으로 보고 그 전환을
     fail-closed 로 처리한다.
4. 새 임대의 투입을 재개한다.

- 전환 드레인이 시간 안에 끝나지 않으면 결속을 옮길 길이 없다. 처분은 파티션 격리가
  아니라 **장치 전체 격리 + 장치 reset** 이다. 장치 reset 이 무엇을 지우는지는 WaveTensor
  에 확인을 요청했다(§5.3).
- **v1.0 한계:** HP-3 때문에 명령 링 데이터 경로가 없고 일의 원천은 외부 제시다
  (`e-defined.typ:716`). Y4 는 그 원천을 멈출 수 없으므로, v1.0 에서 ACTIVE_PART 의
  격리는 장치 판정만으로 서지 않는다(판정 뒤 도착하는 옛 임대의 일). 그래서 v1.0 의
  ACTIVE_PART 는 오늘의 내부 포트 결속(`hiuReq.part`)을 MMIO 로 바꾸는 표면이고, Y4 는
  mock 으로만 검증한다. 격리 주장은 투입 정지 수단(명령 링 소비 회로)이 착지한 판에서 한다.

### 2.5 부팅 순서

**reset 뒤 소거 구간 (HP-5 — WT 제안 · Y4 조건부 동의):**
- 선택자 표 소거(`0xF08[0]` = 0) 동안 정렬된 `0xF00`/`0xF04` 쓰기는 정지한다(정본 —
  `03-hiu.typ:981-990`; `0xF08[0]` 의 뜻은 `e-defined.typ:462-463`). 읽기 처분은 정본이 정하지
  않았다(`03-hiu.typ:1354`). WT 제안(재구현 사실의 규범화)과 Y4 조건(2026-10-05 답 ⑤ (a)):
  `0xF00`–`0xF3F` 는 읽을 수 있고 `0xF08` FP_STATUS 가 폴링 대상이다. 정지하는 것은 *정렬된*
  FP_PROG/FP_BIND 쓰기뿐이고, 비정렬 쓰기와 `0xF08` 쓰기는 즉시 거절 + `[6]` 이다.
- 사상표(`0x400`–`0xBFF`) 소거 동안 쓰기는 정지하고 읽기도 기다린다. 소거 완료를 알리는
  비트가 없다 — Y4 는 init-done 비트나 「`0xF08[0]` = 1 ⇒ 사상표 소거도 완료」 문면을
  요청했다(v1.x 가능).
- 수락되지 않은 접근은 효과도 응답도 없다.

**마스킹 · 변환 초기화 (Y4 이행):** 호스트 재부팅에 맞춰 장치가 reset 되었음이 확인되지
않으면 다음 순서로 한다. 장치가 재부팅을 건너 reset 되지 않으면 옛 부팅의 유효 파티션
논스와 겹쳐 Y4 결함 없이도 `[12]` 가 설 수 있다 — 이 순서가 그것을 막는다.
1. 드레인을 관측한다.
2. 모든 실재 파티션에 `0xE00` flush 를 쓴다(E.9 4항 「키 변경은 해당 파티션의 flush 와
   함께만 일어난다」, `e-defined.typ:1524`).
3. 모든 실재 파티션에 빈 임대 키 · 논스(§3.1 과 같은 I3 경로 — `lease_serial` 하나와 `NonceAllocator` 값 하나 소비)를 기입한다(전 파티션 마스크 유효 하강 — `:339` · `:343`).
4. 파티션마다 `MASK_REKEY` 를 발화하고 §2.3 ⑷ 대로 완료를 확인한다. `[12]` 비교는 유효한
   *타* 파티션만 보므로(`rtl/…/mask/MaskUnit.scala:366` @645bed0 `maskValid(q) && (U(q, partW bits) =/= io.rekey.part)`) 이 순서에서는 잔여 논스와 겹치지 않는다.
5. 소유 페이지를 회수하고 ACTIVE_PART 를 설정한다.

### 2.6 `[12]` 원인 귀속 (Y4 이행 · 캡처 워드는 Y4 제안)

`[12]` 는 「마스크가 유효한 두 파티션이 같은 논스를 지고 있다」는 *건전한* 신호다
(`e-defined.typ:1568-1571`). 물을 것은 그 상태를 누가 만들었는가다. 원인이 Y4 쪽이면 Y4 의
검증된 장부가 틀린 것이고, 장치 쪽이면 Y4 의 상태는 멀쩡하다. 처분이 달라야 한다.

**Y4 논스 장부.** Y4 는 실재 파티션마다 「지금 장치에 기입한 논스 · 기입한 부팅 · 마스크
유효 여부」를 기록한다(`lease_capability.md` I3). §2.5 부팅 순서 뒤에는 모든 실재 파티션이
이번 부팅에 기입한 논스로 유효하다.

**귀속 순서** (`[12]` 를 본 즉시, 그 HIU 의 투입을 멈춘 상태에서):
1. 장부에서 마스크 유효 파티션끼리 같은 논스가 있는가? 있으면 **Y4 의도 결함**
   (`NonceAllocator` · 장부 결함).
2. 없으면 `0xEC4` 캡처를 읽는다(합의된 경우). 겹친 파티션 q 마다:
   - q 가 이번 부팅에 Y4 가 기입한 적이 없으면 **Y4 절차 결함** — 부팅 초기화를 건너뛰었거나,
     장치가 재부팅을 넘어 상태를 지녔는데 Y4 가 reset 을 가정했다.
   - 그 밖(장부의 p 새 논스와 q 논스가 다르고 둘 다 이번 부팅에 기입)이면 **장치 쪽**: 기입
     경로 · 저장 · 비교기 결함. 논스는 WO 라 되읽을 수 없으므로 Y4 기입 경로 결함과 장치 결함은
     더 나누지 못한다. 둘 다 Y4 의 검증된 장부 밖이다.
3. 캡처가 없으면(합의 전 · 캡처 무효) **귀속 불가**.

**처분** (`proofs/verus/src/error.rs` `fault_disposition`):

| 원인 | 오류 | 처분 |
|---|---|---|
| Y4 의도 결함 · Y4 절차 결함 | `LeaseInvariant` | 하이퍼바이저 정지(fail-stop) — 다른 임대의 키 · 논스 장부도 믿을 수 없다 |
| 장치 쪽 · 귀속 불가 | `DeviceFault` | 장치 격리 — 그 HIU 의 모든 임대 회수, 장치 reset, 결함 표시. 하이퍼바이저와 다른 장치는 계속 돈다. 귀속 불가는 기록에 「원인 미귀속」으로 남긴다 |

- 귀속은 진단이지 복구가 아니다. 어느 경우든 그 임대는 실패다.
- Verus: `fault_disposition_separates_origin` — 하이퍼바이저 정지는 원인이 Y4 쪽일 때와만
  동치이고, 장치 쪽 · 귀속 불가는 정지에 이르지 않는다.

## 3. Lease attribute → 구성 표면 매핑

| Lease attribute (`lease_capability.md` §1) | 구성 표면 | 비고 |
|---|---|---|
| `partition_id` | `0xC00` 창 기저 `addr[8:7]` · `0xE00` · `0xEA0` · `0xEBC` · `0xE14` 의 `[7:0]` | 동시에 보유되는 임대 ≤ 실재 파티션 수(`0xFF8[7:0]`) ≤ 4 |
| `key` (256-bit) | `0xE80`–`0xE9C` (MASK_PART 창) | WO. 게스트는 보지 못한다 |
| `nonce` (192-bit) | `0xEA4`–`0xEB8` (MASK_PART 창) | WO |
| `dva_map` — 임대별 장치 VA 사상 (VPN → 프레임 · 권한) | `0xC00 + (p≪7)` VPN · FRAME · COMMIT | 권위는 Y4 의 사상이고 장치 항목은 캐시다. Y4 는 상주를 추적하지 않고 미적중마다 사상에서 채운다. 임대 간 분리는 창 인코딩 + 거절 + 파티션 간 비축출(결과 (c))이 준다 |
| (스케줄 상태) 지금 패브릭을 쓰는 임대 | `0xE14` ACTIVE_PART | §2.4 |
| 소유 페이지 집합 (Y4 가 cap 밖에서 추적) | `0x208` OWN_SET / `0x20C` OWN_CLR | zero-copy 의 소프트웨어 규약 (zero-copy 자체는 재구현 미구현, `03-hiu.typ:1259`) |

- 장치 버퍼 프레임은 PA < 2^44(16 TiB) 여야 한다(프레임 32b). Y4 할당기는 장치 버퍼를
  그 아래 풀에서만 내준다. 그 풀이 없는 플랫폼은 v1.0 에서 지원하지 않는다 — 정본 E.2
  해설(`e-defined.typ:817-820`)이 짚은 「희소한 물리 주소 배치」 위험의 Y4 쪽 처분이다.
- 장치 가상 주소 공간(v1.0 에서 VA 44b)은 Y4 가 관리한다. 게스트가 사상을 요청하는 표면은
  `y4_abi.md` 소관이다.

### 3.1 회수 (release / expiry / revoke)

1. Y4 가 호스트 측 cap-table 에서 token 을 무효화한다.
2. §2.3 의 ⑴–⑷ 를 「빈 임대」로 수행한다. 빈 임대의 키·논스도 §3.2 와 같은 경로로
   짓는다(`lease_serial` 하나와 `NonceAllocator` 값 하나를 소비) — 그래서 §3.2 의 유일성이
   모든 회전을 덮는다. 이것이 옛 키를 덮어쓰는 Y4 측 이행이다. 장치 측 키 바이트 소거는
   정본에 규범이 없다(G1 — §5.1 항목 1).
3. 그 파티션의 소유 페이지를 `0x20C` 로 회수한다.

### 3.2 `(키, 논스)` 유일성 — Y4 의무

- 논스: 단조 카운터 + 호스트 식별자 prefix (`lease_capability.md` I3).
- 키: 호스트 마스터 시크릿에서 `(파티션, 임대 일련번호)` 로 유도한다(KDF).
- 빈 임대도 같은 경로를 쓴다(§3.1).
- 신선도 근거: 호스트 마스터 시크릿은 **부팅마다 새로 짓는다**(임대는 재부팅을 넘지
  않는다). 그래서 카운터가 부팅마다 0 부터 다시 시작해도 쌍이 반복되지 않는다.
- 정본의 「논스는 파티션마다 다르다」(E.9 2항 첫 절)도 전역 단조 카운터로 함께 만족한다.
  단 한 부팅 안에서만 무조건 참이다 — 장치가 재부팅을 건너 reset 되지 않으면 옛 부팅의
  유효 논스가 남는다. 그래서 §2.5 의 초기화 순서가 이 절의 전제다.
- 정본에는 호스트가 읽을 난수 워드가 없으므로, **장치 엔트로피에 의존하지 않는다.**
  마스터 시크릿의 엔트로피 원천은 호스트 쪽(`hw_mechanism_abstraction.md` 레지스트리)이다.

## 4. 인터럽트 / 폴링 (닫힘 — Y4 확정 답 3a, H3-6)

- **기본은 폴링이다.** 폴링 대상은 완료 링(`0x310` CQ_TAIL, `0x340` CQ_WINDOW), 미적중
  정지(`0xE04`), 그리고 fault(`0xF88` FAULT_SUMMARY → `0xF80`)다.
- 인터럽트는 **선택적 가속(opt-in)** 이다. `0x324` IRQ_MASK 를 RMW 로 갱신해 `[0]` 을 0 으로
  한다(§1.2.1). 원천은 완료 링 삽입이다(E.6).
- PCIe MSI-X 벡터 결선은 RTL 변경이 아니라 보드 층의 일이다. v1.x 에서 「완료 IRQ 의
  MSI-X 결선」으로 다룬다(H3-3 · H3-6).
- **fault → IRQ (G2, Y4 제안 · v1.x 후보 — 2026-10-05 답에서 고침):**
  - 처음 낸 형태(`IRQ_MASK[1]` reset 1, 0 = 켬)는 v0.1 문면의 드라이버에게 하위 호환이
    아니었다. `[0]` 을 0 으로 쓸 때 워드 전체에 0 을 쓰는 드라이버는 v1.x 장치에서 fault IRQ 까지
    켠다. IRQ 는 레벨 출력이라(`rtl/generated/CompletionUnit.sv:194` @645bed0 `io_irq = (irqSticky
    && (! irqMask))`) fault 를 모르는 그 드라이버는 내리지 못한다. §1.2.1 의 RMW 의무를 지키는
    드라이버에게는 원래 형태도 무해하지만, Y4 는 의무를 어긴 드라이버에게도 fault IRQ 가
    켜지지 않는 별도 워드를 권한다.
  - 고친 형태: 미배정 `0x32C` FAULT_IRQ_EN(RW, `[0]` 1 = 켬, reset 0). `IRQ_STATUS[1]`(fault
    요약, sticky)은 EN = 1 일 때만 *선다*. 이미 선 `[1]` 은 `IRQ_CLEAR[1]` 로만 내린다.
    `IRQ_MASK` 는 건드리지 않는다.
  - 함께 정할 것: `[1]` 의 세움 원천(FAULT 0→1 에지 / SUMMARY 레벨) · 같은 사이클 해제와의
    경합 · 해제 순서(FAULT_CLEAR → IRQ_CLEAR[1]) · IRQ 선 식.
- 엔트로피 건강성은 `0xF80[17]`(sticky, `0xF84` W1C)로 폴링 관측한다. 재구현에는
  엔트로피원 유닛이 아직 없어서 상수 0 이다(`03-hiu.typ:1256` · `:1279` @645bed0).

## 8. 이력 — v0 레지스터 표 (장치에 없음)

v0(2026-05)은 legacy 참조 구현을 기준으로 `BAR0 + 0x000`–`0x110` 에 다음 워드를 두었다.
재구현 장치는 합의 전 그 구간에 워드를 두지 않는다. 그래서 쓰면 거절 + `[6]`,
읽으면 0 이다(HP-1). 아래는 대응 관계만 남긴 것이다.

| v0 워드 | v0.2 처분 |
|---|---|
| `0x000` HIU_VIRT_ADDR · `0x008`/`0x00C` HIU_DMA_DATA_IN/OUT · `HIU_CTRL.dma_req` | 삭제 — 호스트 발행 DMA 단발 없음 (§2.1, G4) |
| `0x010` HIU_CTRL `ats_req`/`pri_req` · `0x014` HIU_STATUS `ats_resp`/`pri_resp` | 삭제 (기능 재도입은 v2 — §5.3, H2-1/2) |
| `HIU_CTRL.context_switch` (전 파티션 · shadow 동일 사이클 무효화) | `0xE00` 파티션별 flush + §2.3 회전 (H1-3). 전역 flush 금지 |
| `HIU_CTRL[7:6]` partition_id | 키 창 역할 → `0xEA0` MASK_PART · 값 → `0xE00`/`0xEBC` · 주소 → `0xC00` 창 기저 · 「현재 HIU 파티션」(요청 결속) 역할 → `0xE14` ACTIVE_PART (WT 제안, §2.4) |
